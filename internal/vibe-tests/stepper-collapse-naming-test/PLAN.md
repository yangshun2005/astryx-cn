# Stepper 折叠摘要命名 Vibe 测试

**状态：** 临时性 · 第 1 轮已完成 · 已定案
**相关：** [`../README.md`](../README.md)（Checker Protocol）、[API 仲裁](https://github.com/meta/astryx/wiki/API-Arbitration)、[设计 Vibe 测试](https://github.com/meta/astryx/wiki/Designing-Vibe-Tests)、[PR #5659](https://github.com/meta/astryx/pull/5659)

---

## 1. 问题

PR #5659 为 `Stepper` 增加了窄宽度折叠：标签消失，只剩一条裸的分段轨道，其下方出现一行，显示当前步骤的名称，并在设置了 `onStepClick` 时显示上一页/下一页控件。

PR 反馈：在移动端，这一行的两半往往都是多余的，因为使用方已经有自己的返回/继续按钮和自己的每步标题。本仓库的两个向导模板都是这种形态——`form-wizard` 和 `checkout-wizard` 都传入 `onStepClick`，以便用户在全宽下向后跳转，并且各自都有页脚按钮和每个面板的 `<Heading level={2}>`。

所以每一半都需要一个关闭开关。**它们应该叫什么，应该是两个 prop 还是一个？**

## 2. 设计

按[设计 Vibe 测试](https://github.com/meta/astryx/wiki/Designing-Vibe-Tests)的四要素输入。

**目标与度量。** 一个朴素的 agent 被告知*页面*提供了什么，从不被告知 prop 名称。按正确性、幻觉、直接性和置信度校准评分。平局决胜：先幻觉，再概念更少。

**提示词组。** [`prompts.json`](prompts.json) 中有四个提示词，对应 2×2 网格中周围页面已有内容的每个格子。没有一个提示词提到 prop、值或"collapse"一词。

| | 页面已有 | 正确答案 |
| --- | --- | --- |
| p1 | 页脚返回/继续 | 关闭控件，保留名称 |
| p2 | 每步标题 | 关闭名称，保留控件 |
| p3 | 两者都有 | 两者都关闭——裸轨道 |
| p4 | 两者都没有 | **什么都不设置**（阴性对照） |

**实验组。** 四种条件，外加一个回忆探针。

| 组 | 形态 |
| --- | --- |
| `A` | `hasCollapsedControls` / `hasCollapsedLabel`，均默认 `true` |
| `B` | `hasControls` / `hasLabel`，均默认 `true` |
| `C` | `hasSummaryControls` / `hasSummaryLabel`，均默认 `true` |
| `D` | `collapsedSummary?: 'auto' \| 'label' \| 'controls' \| 'none'` |
| `recall` | 描述行为，故意不命名 prop——由 agent 写出它期望的名称 |

**编排。** 每个（提示词 × 组）一个隔离子 agent，用 wiki 的空白状态前言全新启动，自我报告但从不自我评分。五个回忆样本。一个具有跨组可见性的评判 agent。共 22 个 agent。

### 公平性（Checker Protocol）

| 不变量 | 本测试如何遵守 |
| --- | --- |
| §1 公平的评估者 | 一个评判者，所有组并排，一套评分标准。此处无法盲评——组别从 prop 名称即可辨认——因此要求评判者按评分标准打分而非凭个人偏好，并在阅读任何结果前审计文档对等性 |
| §2 只有被测系统变化 | 四份组的文档**由同一模板机器生成**（[`gen-docs.mjs`](gen-docs.mjs)）；引言、prop 表行、`Step` 描述、示例 1 和反模式逐字节相同。349/349/349/354 词。命名 prop 的散文是一句话，只替换名称，因此没有组获得词汇上的先发优势 |
| §3 绝不泄露答案 | 标准答案存于 `prompts.json`，从未到达生成 agent |
| §4 代表性环境 | 技能文档正是使用方的 agent 所获得的内容 |
| §5 无上下文 | 全新子 agent，明确禁止阅读仓库、组件源码或彼此的文档 |

## 3. 发现

### 3.1 识别是四路平局

**16/16 正确。16/16 无幻觉。** 每个组在每个提示词上都给出了正确配置，包括 p4 阴性对照，没有任何组的 agent 被诱使去碰它。直接性仅在一个结果上出现分歧（`c-p2` 添加了一个未被要求的 `<h1>`）。

按 wiki 的决策模式，*所有选项产生相同代码 → 差异无关紧要，选更简单的那个*。在这组提示词上，命名不改变 agent 能否使用 API。以下全部是平局决胜。

### 3.2 回忆探针是各组拉开差距的地方

五个 agent 获得行为描述，故意不命名 prop，被要求写出它们期望的名称。

| 样本 | 控件 | 名称 |
| --- | --- | --- |
| 1 | `showCollapsedControls` | `showCollapsedStepLabel` |
| 2 | `showCollapsedControls` | `showCollapsedLabel` |
| 3 | `showNavigation` | `showStepLabel` |
| 4 | `showSummaryControls` | `showSummaryLabel` |
| 5 | `showSummaryControls` | `showSummaryLabel` |

**5/5 产生了两个独立布尔值。没有人产生枚举。** 每一个都在无提示下拒绝了枚举，并得出相同理由——它迫使你重述你不想改变的那一半。样本 5 给出了最尖锐的版本：组件现有的枚举（`orientation`、`density`、`indicatorPosition`）都是互斥选择，而这个不是。**组 D 因形态出局**，尽管正确性得分为 5.00。

**4/5 拒绝了裸 `Label`，因为它与现有 `label` prop 冲突**——整个序列的可访问名称。样本 3：*"读者会以为它切换那个字符串。"* 样本 2 也指出了另一半：*"单独的 `showControls` 听起来像抑制 `onStepClick`。"* **组 B 因歧义出局**，而且这是发布 API 中的真实冲突，不是测试的产物。

剩下 A 和 C，2–2。两件事打破僵局：

- **两个选 `Summary` 的都从 `Collapsed` 开始然后切换**，且都说明了原因：反模式中的 `data-astryx-stepper-summary` 选择器看起来像组件的内部名称。样本 4：*"`showCollapsedControls` 是我的第一直觉……但 data 属性指向 'summary' 作为内部名称。"* 这是猜测实现的理由，不是使用方会想到这个词的理由。
- **3/5 明确拒绝 `Summary` 作为内部词汇。** 样本 3：*"'summary' 是内部实现词汇，在散文或 prop 表中从未出现。"*

### 3.3 评判者选 A，基于分数未显示的效果

> "在 p2 和 p3 上，每个 B 和 C 结果都停下来验证该 prop 不会杀死桌面标签（4/4），而没有任何 A 或 D 结果这样做（0/4）。"

名称中的 `Collapsed` 一词消除了一类关于作用范围的疑虑。`Summary` 不能，因为一个尚不知道该行叫 summary 的读者无法判断该 prop 触及哪里。

评判者还发现了枚举特有的反转风险：其值命名的是*幸存*的内容，而每条需求命名的是要*移除*的内容。`d-p2` 当场踩了进去——*"我的第一直觉是把它设为 `'none'`……`'none'` 是最字面地移除名称的值"*——仅通过提示词中一个无关从句才恢复。

### 3.4 对 LLM 而言 `show` 胜过 `has`，但约定仍应胜出

**5/5 回忆样本产生了 `show*`**，几个明确因双重否定而拒绝 `hide*`。Astryx 在 `packages/core/src` 中约有 30 个 `has*` 布尔值，零个 `show*`，所以内部约定是 `has*`。

采用约定。§3.1 是它免费的证据：当文档写 `has*` 时，agent 16/16 正确使用了 `has*`。前缀影响 agent *猜测*什么，不影响它对有文档的 API *做*什么——而设计系统的 prop 总是有文档的。

### 3.5 比命名更重要的发现

每个组都撞上同一堵墙，这是设计的属性而非任何名称的属性。**没人能判断折叠轨道是否仍可点击。** `d-p1`：

> "可能根本没有办法点回已完成的步骤——标签没了，我又抑制了控件……这是简报中两个手机需求可能相互紧张的唯一地方。"

完全正确，且同样适用于 `a-p1`、`b-p1` 和 `c-p1`。在 `separated` 布局中，步骤点击目标随标签一起消失，所以关闭控件后就没有可点的东西。已在发布的 `hasCollapsedControls` JSDoc 中处理，其中点明了后果和 `on-track` 例外，而不是留待发现。另外两个跨组发现记录在 §5 作为后续事项。

## 4. 决策

**发布组 A——`hasCollapsedControls` 和 `hasCollapsedLabel`，均为 `@default true`。**

- 两个布尔值，因为回忆探针 5/5 产生了两个布尔值，且四种状态确实独立（§3.2）。
- `has*`，因为该约定在 `packages/core/src` 中一致，且 §3.1 表明该前缀在使用中零成本（§3.4）。
- `Collapsed` 限定词，因为它在 4/5 回忆样本中是无提示的第一直觉，因为它在评判者的阅读中可测量地消除了作用范围疑虑（§3.3），也因为 `Summary` 只靠泄露内部名称才赢过（§3.2）。
- 默认值保持 `true`：报告是关于冗余，不是破坏，且一个传入 `onStepClick` 而无其他导航的使用方不能在手机上陷入困境。

实现说明：`Step` **无需改动**。它已经以 `summarySlot != null` 作为摘要 portal 的门控，所以不提供该 slot 就是 `hasCollapsedLabel` 的全部实现——而且因为该行是 `aria-hidden` 而 `<ol>` 保留每个步骤的名称，两个 prop 都是纯视觉的，不会缩短屏幕阅读器听到的内容。

## 5. 本测试暴露的后续事项（非命名）

1. **没有每步门控。** p1+p3 上全部 8 个结果都独立地在 `onStepClick` 周围写了相同的 `index < step` 守卫，因为没有任何东西让步骤声明自己不可达。`a-p1` 注意到了由此产生的矛盾：*"我的守卫让未来步骤看起来可交互却什么都不做，这与反模式部分提出的 tab 顺序抱怨相同。"* 值得一份规范。
2. **折叠无法强制。** 全部 16 个都报告无法预览或固定折叠状态。这是测试和 Storybook 的缺口，也是这里单元测试必须手动重定义 `clientWidth` 的原因。

## 6. 注意事项

- **p1 在四个组中都是送分题。** 每份文档中的示例 2 几乎逐字渲染了 p1 的答案。对称，所以不偏向任何组，但这意味着只有 p2/p3/p4 携带信号，§3.1 中的 16/16 比看起来更容易。评判者独立发现了这一点；重跑应改变示例演示哪个格子。
- **两个限定词都被预置了，且不均匀。** "collapsed" 在回忆文档中出现 4 次（散文中 3 次），"summary" 一次，在 CSS 选择器内。因此 `Collapsed` 有更大的提示词侧优势——这使得 2–2 的分裂在朴素阅读下*有利于* `Summary`，也是 §3.2 依赖切换叙述而非原始计数的原因。
- **回忆 n=5，每组 n=4。** 一致的结果（枚举 0/5、双布尔 5/5、`show*` 5/5、`label` 冲突 4/5）远超采样噪声。2–2 的限定词分裂则不然，由 §3.3 而非计数决定。
- **一组提示词，一位作者。** 由起草候选方案的同一个人撰写。
- **回忆将三个场景批给每个 agent**，偏离了每提示词一 agent。有意为之：命名一个连贯的*对*是现实行为，拆分它只会测量三个不相关的猜测而非一个方案。
