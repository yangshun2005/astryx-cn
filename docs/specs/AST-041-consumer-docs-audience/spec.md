## 意图

Astryx 向调用方交付的文档，服务于使用 Astryx 构建产品的人和智能体。文档通过 `astryx docs`、`astryx search`、组件、Hook 和模板文档、`--json` API、生成的智能体指南以及文档站点触达他们。调用方必须能对读到的所有内容采取行动。关于构建 Astryx 本身的材料属于贡献者知识。

本记录掌管通过上述消费者界面交付的每一份文档的受众边界，包括集成所贡献的文档。

## 非目标

- 贡献者文档、知识记录和仓库说明。
- 文档结构、图标识和调用方文档的质量标准；这些由文档契约掌管。
- 满足本契约的等效内部实现仍然有效。

## 要求

- **FR1 — 交付的文档面向调用方。** 交付文档的每一节都必须描述调用方能够使用或依赖的内容：用途与替代方案、API 与默认值、可观察行为及其保证、组合方式、调用方继承的成本与义务、主题化接缝、迁移，或他们能依据公开证据对使用 Astryx 创建的产品界面或构建产物应用的质量标准。
- **FR2 — 排除维护者流程。** 交付文档不得要求读者为 Astryx 维护者产出证据、满足 Astryx 的内部评分或晋升标准、遵循 Astryx 的贡献生命周期，或运行 Astryx 自己的测试和 CI 工具。这类材料属于掌管该主题的贡献者界面，或在没有特定界面时属于贡献指南。它绝不默认回到交付文档。
- **FR3 — 系统保证保留，作为保证陈述。** 调用方可依赖的系统行为事实必须留在交付文档中，并作为对调用方的保证来陈述。例如，"主题目标一旦发布即稳定"面向调用方；"审查者必须检查主题目标是否稳定"则不是。调用方事实被写成维护者措辞时，修复方式是改写，而不是移走。
- **FR4 — 分发受众不是读者角色。** 文档的分发受众决定哪个编译包包含它，例如公共包或内部包。它不得让维护者流程材料进入任何包。内部包仍然是面向使用 Astryx 构建产品的人。
- **FR5 — 执行检查衡量所面向的读者。** 用于把关 FR2 的自动化检查必须按内容所面向的读者分类，而不是按是否出现某个词。在把关之前，它必须在交付语料上显示零发现，并至少捕获一个真实违规。包含被标记术语的调用方指令，例如"对变换做动画以保持合成器提升"，必须通过。每条发现必须指明文档和章节，并说明该材料应归属何处。检查必须为合法的面向调用方用法提供明确、可审查的豁免。
- **FR6 — 贡献的文档遵循相同边界。** 集成贡献到消费者界面的文档必须满足 FR1–FR4。集成编写参考必须声明此规则。
- **FR7 — 共享调用方评分标准只有一个所有者。** 交付的 `is-my-code-good` 指南必须拥有关于调用方创建的产品代码是否良好使用 Astryx 的共享标准。专门评分标准可以添加权重和特定于构建产物的检查，但必须链接到共享标准，而不是重新定义它们。调用方评分标准必须使用公开输入，并且必须将缺失证据报告为未检查，而不是通过。

## 当前状态影响

交付的主题目录有一个 README，说明了调用方行动测试、维护者写作的常见迹象以及该材料的归属。仓库说明声明了相同的受众。FR7 将共享的面向调用方评分标准分配给 `is-my-code-good`；其指南和专门链接是本次仅规范变更之外的配套实现。尚无自动化检查执行受众边界。编写类型为文档图声明了一个分发受众字段，具有 public 和 internal 值；目前还没有任何东西读取它。FR4 将该字段与读者边界分开。

本次仅规范变更不改变任何运行时行为或已发布包，不需要 Changeset。

## 决策日志

### DEC-1 — 调用方行动测试定义边界

**参考：** `spec:AST-041/DEC-1`
**决策者：** `josephfarina`，`2026-09-23`

交付文档触达使用 Astryx 构建产品的智能体和人，每个额外章节都消耗他们的注意力。测试标准是调用方是否对内容采取行动。系统保证即使听起来像流程也能通过该测试，因此它们为调用方改写，而不是移走。

否决：因维护者材料准确而将其保留在交付文档中，以及因调用方保证被措辞为流程而将其移出。

### DEC-2 — 按所面向的读者执行，并衡量精确度

**参考：** `spec:AST-041/DEC-2`
**决策者：** `josephfarina`，`2026-09-23`

嘈杂的检查会被抑制而不是被处理。把关必须证明它能捕获真实违规，并通过与维护者流程共享词汇的调用方指令。

否决：将裸词表作为把关，以及将分发受众用作维护者材料的存放处。

### DEC-3 — 调用方拥有的质量审查留在交付文档中

**参考：** `spec:AST-041/DEC-3`
**决策者：** `josephfarina`，`2026-10-09`

使用 Astryx 构建产品的人或智能体可以对评估其自身产品代码的公开标准采取行动。`is-my-code-good` 指南拥有共享标准；特定于构建产物的指南链接到它，只添加自己的检查或评分。缺失证据保持可见，而不是变成通过。

否决：将每个质量评分标准都视为维护者流程，以及将共享标准复制到每个特定于构建产物的指南中。
