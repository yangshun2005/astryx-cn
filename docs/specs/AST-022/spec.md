# 主题所有权、继承与物化系统规范

## 意图

主题作者需要知道一个主题是跟随另一个主题，还是仅将其作为起点。`defineTheme({extends})` 有意保留对已解析基础主题的源依赖。当作者希望从基础主题获得修复、新组件覆盖和其他更新时，这很有用，但升级依赖时也可能改变子主题。

因此 Astryx 应支持两种明确的工作流：

- **跟随：** 保留 `extends`，继续采纳基础主题的变更。
- **拥有：** 将当前创作输入解析为可审查的本地源码，不再依赖所选基础主题或可变的生成公式。

物化是获取完全拥有快照背后的共享技术操作。它解析继承和生成的主题创作值，预览确切变更，并仅通过单独的显式写入调用写出等效的本地主题，不通过提示或从 stdin 读取。

## 非目标

- 改变 `defineTheme({extends})` 当前的含义或优先级。
- 在本规范 PR 中移除 `extends`、排版、动效、圆角或颜色配置。
- 定义色调调色板生成、可接受的调色板验证、语义颜色推荐或上下文对比度分析。
- 定义作者如何在 Astryx 内置尺度之外创建新的排版、间距、动效或圆角值。主题本地尺度扩展由单独的 AST-023 提案负责。
- 承诺快照在 Astryx 包升级时冻结组件实现。它冻结的是主题创作输入，而非消费这些输入的库代码。
- 将任意可执行 React 节点或函数序列化为普通数据。
- 在没有作者可见预览和显式写入决策的情况下更新、覆盖或分离主题。

## 术语

- **跟随主题：** 带有 `extends` 关系的源码。重新解析时可能采纳所选基础主题的变更。
- **完全拥有快照：** 包含公共主题创作契约暴露的每个已解析值的本地主题源码。复现它不需要所选基础主题或可变的尺度生成行为。
- **物化：** 将继承和生成的创作输入解析为显式、可审查的本地源码。
- **分离：** 物化一个跟随主题并移除其 `extends` 关系。
- **冻结：** 物化选定的生成尺度，同时保留任何预期的继承关系。
- **血缘绑定本地令牌：** 一个主题本地名称，其声明和使用仅通过拥有它的已注册精确 `extends` 血缘有效。
- **未解析可执行值：** 工具无法安全地表达为生成源码的继承图标、指示器、语法定义或其他值。

## 选择生命周期

该选择控制谁负责未来的主题变更。两种选项都不是普遍更好的，因此创作工具必须在写入前解释两者。

| 选择                         | 优势                                                                                                                                                 | 权衡                                                                                                                                           | 最适合                                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 通过 `extends` 跟随基础主题  | 源码更小；接收已审查的修复、新主题覆盖和来自基础主题的协调更新；便于相关变体。                                                                       | 升级基础主题可能改变子主题；审查者必须考虑继承的变更；复现源码需要基础依赖。                                                                   | 有意与另一主题保持一致的变体，尤其是两者一起维护时。                                                         |
| 获取完全拥有快照             | 每个公共主题值都是显式且本地可审查的；基础主题和 Core 默认值变更不会改变已保存的值；作者可以自由分化。                                               | 源码更大；作者维护复制的值；不会自动采纳来自原基础主题的后续修复和新覆盖。                                                                     | 优先考虑控制和视觉稳定性的产品或应用主题。                                                                   |
| 分离现有主题                 | 保留主题当前的已解析值、名称和导入，同时结束先前选择的基础关系。                                                                                     | 产生更大的变更以供审查；未来的基础改进需要显式比较和采纳。                                                                                     | 作者后来决定拥有其当前外观的跟随主题。                                                                       |
| 冻结选定的生成器             | 使选定的生成值显式，而无需完全分离。                                                                                                                 | 保留的基础和生成器依赖仍可能改变其他值；结果是部分物化，而非完全拥有。                                                                         | 希望控制一个尺度同时有意继续在其他方面跟随的主题。                                                           |

CLI 必须用这些术语描述所选结果。对于仍依赖未报告的基础主题或可变生成器的输出，它不得使用"自包含"、"已分离"或"完全拥有"。

## 需求

### 显式生命周期选择

- **FR1 — 跟随和拥有是不同的承诺。** 从现有主题启动新主题的工具必须将跟随基础主题和获取完全拥有的起点作为显式选择呈现。它必须解释跟随会接收后续基础变更，而拥有接受本地维护，并且必须在写入前要求显式选项选择其一。当选项缺失时，CLI 必须返回可用选择，不写入或读取 stdin。工具可以根据作者陈述的目标推荐一个选择，但不得静默选择它或将 `extends` 描述为完全独立的副本。
- **FR2 — 跟随保留当前 `extends` 语义。** 跟随主题保留其基础依赖，并可在有意更新依赖后采纳基础主题的已解析令牌、组件、媒体表面、图标、指示器、语法和本地令牌变更。生成的 `DefinedTheme` 在消费时仍保持扁平化，但运行时或构建时的扁平化不得呈现为源码独立性。
- **FR3 — 拥有的起点写入本地源码。** 仅将基础主题作为起点选择必须创建完全拥有快照。所选基础主题或 Core 主题默认值的后续变更不得改变其保存的主题值，除非作者显式运行迁移或比较工作流。

### 物化边界

- **FR4 — 物化覆盖可配置的主题表面。** 该操作必须考虑继承值和由当前排版、动效、圆角和颜色配置生成的值。它必须保留显式令牌和显式组件的优先级。它还必须清点本地令牌、`onDark`、`onLight`、语法、图标和指示器，而非静默丢弃它们。
- **FR4a — 分离不能原样复制血缘绑定本地令牌。** 在移除 `extends` 之前，工具必须检查继承的本地令牌声明、所有者元数据和每个可达引用。继承名称仅通过其精确注册的基础血缘有效；将该名称复制到分离主题中会使其成为外来声明，并导致当前验证器失败。因此分离必须在写入前停止，并要求在拥有主题规范下审查的显式本地令牌迁移。该迁移必须将受影响的名称映射到分离主题的命名空间，重写每个可达声明和引用，并保留已发布令牌契约所需的任何兼容别名。如果作者不选择此类迁移，工具必须保留 `extends`，报告血缘依赖，并且不得将结果描述为已分离或完全拥有。
- **FR5 — 物化产生创作源码，而不仅是编译输出。** 仅 CSS 或 JavaScript 构建产物不够，因为它不给作者可编辑的主题定义。输出必须适合提交、审查和使用受支持的主题工具链重建。
- **FR5a — 完全拥有包括所有已解析的公共主题值。** 完全拥有快照必须写入公共主题创作契约暴露的每个值，包括当前等于 Core 默认值的值。仅记录差异的输出仍依赖未来的 Core 默认值，不得标记为完全拥有。
- **FR5b — 创作投影与运行时表示分离。** 物化可以产生更大、完全显式的源码投影，以便作者可以读取、编辑、审查和重建每个已解析值。该投影本身不得强制发布的主题携带相同的扩展数据。
- **FR5c — 预览显示大小权衡。** 写入前，预览必须显示源码投影和等效的编译/运行时输出，包括与当前主题相比产生的 CSS、JavaScript 和包大小影响。当所选所有权选择会增加运行时成本时，检查或编辑已解析视图不得被描述为无运行时成本。
- **FR5d — 回执和创作元数据不进入运行时产物。** 回执、来源、比较证据和仅创作元数据必须保留在 sidecar 或开发输出中，不得打包到运行时 CSS、JavaScript 或包导出中。等效运行时输出必须保留现有紧凑表示或使用等效的去重形式。分离可以接受真实的大小增加，但仅作为显式、预览过的所有权权衡。
- **FR6 — 主题所有权有诚实的边界。** 物化冻结通过当前公共创作契约可表达的主题值。它必须声明使用的 Astryx 版本，并且不得声称冻结内部组件标记、主题契约外的默认样式、浏览器渲染或未来的包行为。
- **FR7 — 主题拥有的调色板引用保持拥有。** 对同一主题已提交调色板文件中精确值的引用默认保持为引用；无需替换为复制的十六进制值。当调色板属于另一个包时，工具必须要求显式选项以保留该可见依赖或在本地复制当前值。

### 可执行值与失败行为

- **FR8 — 可执行值需要保留源码的处理。** 生成的源码可以仅当作者有意保留并报告该依赖时，通过显式导入保留图标、指示器、语法定义或其他可执行值。完全拥有快照必须将继承自所选基础主题的值替换为等效的拥有本地源码或作者提供的本地引用，且不导入原基础主题。当工具无法安全地构造或验证该源码时，操作必须报告确切字段并在写入前停止。如果作者改为保留基础导入，预览和回执必须报告它，结果不得标记为完全拥有或源码独立。工具不得将可执行值字符串化、省略或替换为占位符。
- **FR9 — 写入是原子且需显式选择的。** 预览是默认。写入需要显式作者操作，使用临时目标，验证完整结果，并仅在成功后替换目标文件。现有已修改输出不得在没有单独显式覆盖选项的情况下被覆盖。分离通过添加已解析值并移除 `extends` 来更新所选现有主题；它不创建第二个主题或要求调用者更改导入。
- **FR10 — 部分物化是显式的。** 作者可以选择仅冻结选定的生成尺度，同时继续跟随基础主题。预览和回执必须标识每个保留的依赖。部分操作不得标记为已分离或已拥有。

### 等价性与审查

- **FR11 — 前后解析等效。** 成功的完全物化必须在同一 Astryx 版本下比较原始主题和建议主题。令牌、组件覆盖、媒体表面覆盖、本地令牌声明、本地令牌所有者和血缘元数据以及注册表选择必须匹配。差异会阻止写入，除非作者显式选择记录预期变更的单独迁移。对于本地令牌迁移，等价性证据还必须显示旧到新名称映射、每个重写的引用、应用该映射后的等效已解析行为以及任何所需的兼容别名。编译差异必须限于记录的重新命名和别名，并包含在预览和大小比较中；未解释的外来或未声明名称会阻止写入。
- **FR12 — 预览解释后果。** 写入前，工具必须显示移除的基础或生成器依赖、要创建或更改的文件、未解析的可执行值、保留的依赖和确切的语义摘要。视觉比较可以补充此证据，但不得替代结构比较。
- **FR13 — 每次写入都有回执。** 回执必须包括工具和 Astryx 版本、源主题身份、适用时的原始基础身份和版本、所选操作和表面、输入和输出摘要、保留的依赖、生成的文件路径和验证结果。它不得在运行时被要求。
- **FR14 — 重复输出稳定。** 在相同源码、版本、选项和环境无关输入下，物化必须产生字节相同的生成文件和回执，除非显式排除调用时间。
- **FR14a — 未来比较是只读的。** 完全拥有快照可以稍后使用回执元数据与其原基础主题的较新版本比较。比较必须显式请求，必须显示建议的结构和视觉差异，并且不得自动更新拥有的源码或重建继承。

### 兼容性与迁移

- **FR15 — 现有便捷 API 在迁移存在前保持稳定。** 现有 `defineTheme` 排版、动效、圆角或颜色配置背后的实现不得静默采用不兼容的生成行为。版本控制、弃用或替换需要先有受支持的比较和物化路径。在受支持的调色板生成器、显式映射工作流、视觉比较、迁移命令、文档和兼容性夹具可用之前，`defineTheme({color})` 不得标记为已弃用。移除需要后续的破坏性发布。
- **FR16 — 旧版颜色迁移是显式的。** 将 `defineTheme({color})` 迁移到作者拥有的色调调色板必须使用当前受支持的调色板生成器，产生可审查的调色板和令牌映射，并呈现产生的视觉和结构差异。它不得在未更改的源码下将旧版 HCT 实现替换为新配方。
- **FR17 — 生命周期命令使用平实语言。** CLI 可以暴露不同的 `detach` 和 `freeze` 命令或其他经审查的词汇。帮助和输出必须用跟随更新与拥有快照的术语解释结果。命令必须保持非交互：选择和写入批准使用显式选项或单独的预览和写入调用，绝不使用提示或 stdin。仅内部术语 `materialize` 不足以作为用户指导。
- **FR18 — 当前调色板工作不受阻塞。** AST-022 管辖后续生命周期工具。它不得延迟保留当前 `defineTheme` 边界的可接受调色板、调色板生成、验证或主题采纳工作。

## 建议的作者流程

### 启动主题

```text
选择 Neutral 作为基础主题
            |
            +-- 跟随 Neutral
            |      保留 extends；升级时接收已审查的 Neutral 变更
            |
            +-- 用作起点
                   生成拥有的本地源码；无 Neutral 主题依赖
```

### 更改现有主题

```text
检查依赖
        |
        +-- 从基础主题分离
        |      检查继承的本地令牌血缘
        |      迁移血缘绑定名称或停止
        |      解析继承并移除 extends
        |
        +-- 冻结生成值
              将选定的尺度配置替换为显式本地值

预览 -> 验证等价性 -> 显式写入调用 -> 原子写入 -> 回执
```

确切的命令名称仍是实现决策。一种可能的分工是 `astryx theme detach` 用于继承，`astryx theme freeze` 用于生成尺度，两者都由同一物化引擎支持。

## 当前状态影响

目前，`defineTheme({extends})` 正确地将基础主题扁平化到已解析的 `DefinedTheme` 中，使运行时和静态构建可以消费一个自包含结果。然而，源码作者仍保留对导入基础主题的依赖。更新该包并重建因此可能改变继承的主题值。

排版、动效、圆角和旧版颜色辅助函数也在规范化期间生成值。它们简洁的意图很有用并继续受支持，但在未更改的源码下更改公式可能改变输出。本规范不引入此类变更。它定义了未来的逃生舱，让作者保留简洁配置或有意识地冻结其当前结果。

CLI 有主题模板和构建输出，但目前不提供移除 `extends`、扩展每个受支持的生成尺度、保留源码级注册表引用并验证等效创作源码的通用操作。该实现遵循本建议契约。创建超出内置尺度的新值是相关的创作工作，但由 AST-023 独立规范。

### 完成标准
