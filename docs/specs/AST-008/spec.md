# 创作时色调色板生成系统规范

## 意图

主题作者需要一种可重复的方式来生成完整的色调色板候选。生成属于创作工作：它产出颜色供人检查、调整和接受。被接受的结果保存为私有的、主题自有的色板数据。普通主题构建不会重新运行生成器。

Palette Generator Lab 比较候选配方、完整色系、模式、锚点和现有主题，然后让作者复制候选 JSON。版本化的 OKLCH 配方是受支持生成的视觉基础。后续的现行权威——AST-018，仅在修订并接受后——负责已接受色板数据的形态与生命周期，以及任何一等色板/主题集成。

Astryx CLI 主题创作工作流暴露纯 `generateTonalPalette()` 创作 API 和 `astryx theme palette generate` 命令。两者使用同一个版本化引擎。两者都不会隐式重写主题。

新创作接口推荐色板工作流，不把旧版色阶辅助函数呈现为仿佛选择一个强调色就是一次孤立编辑或一个已批准的色板。Playground 移除其 `Create from accent` 功能，同时保留显式的 token 编辑。

`DefineThemeInput.color`、`ThemeAdaptationValue.color` 和 `expandColorScale()` 是旧版创作接口。在替换优先补丁发布下文所述的完整现代化路径之前，它们保持 `stable`；该补丁将它们移至 `deprecated`。在整个弃用窗口内，它们现有的运行时行为保持受支持且字节等价。弃用是静态的、源码级的：声明、创作校验和文档标明替代方案，不添加兼容标志、运行时分支、渲染应用警告或可执行生产包字节。静态 TypeScript 声明元数据不是可执行的运行时行为。

## 非目标

- 为未来的一等色板选择公共 API、已接受数据形态、语义角色引用模型、编译器集成或运行时投影。后续的现行权威——AST-018，仅在修订并接受后——负责这些选择。
- 在各自单独确定的清理项获批进入次版本发布之前，移除 `DefineThemeInput.color`、`ThemeAdaptationValue.color` 或 `expandColorScale()`。
- 仅为弃用而添加运行时兼容设置、运行时警告、可执行生产分支或可执行生产包字节。
- 要求手工编写或导入的数据提供生成的色板或来源信息。
- 将色板色阶视为设计批准或无障碍保证。

## 创作生命周期

| 阶段       | 必需结果                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 创建       | 生成、手工编写或导入一个完整的候选色板。                                                                                         |
| 审查       | 检查完整色系、模式、诊断、比较和渲染上下文；自由调整或拒绝。                                                                     |
| 接受       | 在已接受色板契约下保存最终精确色板数据。                                                                                         |
| 映射       | 在负责已接受色板/主题集成的权威下，记录可检查的稳定语义角色映射。                                                               |
| 验证       | 在所属主题记录中，为精确色板、角色映射和渲染值记录上下文证据。                                                                   |
| 重新生成   | 从已接受色板一致地更新已映射角色，无需隐式运行生成器或手动重新复制无关角色。                                                     |

## 需求

- **FR1 — 生成是可选的。** 生成、手工编写和导入的色板在通过校验后是平等的。缺少生成来源信息仅意味着“并非由本配方生成”；它绝不能使有效色板数据无效。
- **FR2 — 请求描述完整的作者意图。** 生成请求必须描述完整色系集合；归一化种子；版本化强度和中性配置；精确、有界和灵活锚点；显式色阶布局；亮色和暗色策略；目标色域和编码；以及所有其他影响输出的参数。Astryx 工具应将色系渐变默认设为 21 色阶的 `0, 5, …, 100` 布局，同时接受任何非空的作者定义数字色阶列表。紧凑和专用布局是有效的作者选择，而非例外。每个候选都暴露精确的独立黑色和白色值，用于直接主题创作。色阶 0 和 100 在生成的色系中重复这些值。作者可以通过自定义色阶列表省略重复的端点，而不会丢失独立值。色系标识符 `black` 和 `white` 保留给这些独立值。
- **FR2a — 自定义色阶语法是精确的。** 每个色阶必须是 0 到 100（含）之间的有限 JSON 数字。色阶必须唯一且严格递增。整数和小数色阶均有效；等价数字拼写如 `5` 和 `5.0` 标识同一色阶，因此不能共存。端点 0 和 100 是可选的。单色阶色板有效。序列化使用实现产生的规范 JSON 数字拼写，且不得依赖区域设置。
- **FR2b — 色阶数字是稳定坐标。** 对于相同配方、色系、模式、种子、鲜艳度、配置和兼容锚点，共享色阶在紧凑、完整和自定义布局中必须产生相同的精确颜色。添加或移除其他色阶不得重新编号或改变它。生成的 TypeScript 必须仅暴露请求的色阶键，因此省略的色阶会无法通过类型检查。
- **FR3 — 模式意图是显式的。** 仅亮色、仅暗色、独立的亮色和暗色输入、共享候选，以及命名暗色变换是彼此不同的。亮色渐变不得静默变为已审查的暗色渐变，标签不得为暗色模式而反转。
- **FR4 — 约束和偏好保持区分。** 色域有效性、单调性、精确锚点和有界锚点容差是硬约束。强度、光学平衡和灵活锚点是优化偏好。冲突必须明确失败，而不是移动精确锚点、放宽容差、替换配置或改变色阶布局。锚点不得将色阶 0 或 100 变为彩色值；冲突的端点锚点会失败，并提示使用内部色阶。
- **FR5 — 配方是确定性的且版本化的。** 配方标识必须固定色彩空间、常量、配置、调度、锚点、色域处理、精度、舍入、序列化和平局决胜。相同的归一化请求必须在受支持平台上产生字节相同的规范候选输出，不依赖环境时间、区域设置、路径、网络、随机性、遍历或未记录的依赖输入。
- **FR6 — 生成的候选携带可复现性证据。** 生成器必须输出完整候选，外加一份分离记录，命名归一化请求、配方和实现版本、输出格式版本、调整、偏差，以及每个规范输出摘要。输出变化必须改变匹配的标识或摘要。
- **FR7 — 生成止于候选。** 输出必须标识自身为候选，且不得采纳值、映射角色或声称视觉或无障碍批准。预览是只读的。显式输出选项可以将候选保存为单独的 TypeScript 或 JSON 文件，但未经作者明确意图不得覆盖现有文件。一旦被采纳，色板就是普通的作者自有数据：它可以自由编辑，不再受生成器控制。编辑后的已接受数据不得声称精确重新生成，普通主题构建不得重新运行生成器。
- **FR8 — 所选配方保留完整色系证据。** 第一个生产配方必须由其规范算法和规范夹具固定，而非另一个实现。发布前，其版本固定证据必须覆盖完整色系集合、渲染的亮色/暗色上下文、色相连续性、亮度和相邻色阶区分度、色域、色系平衡、CVD 模拟、可复现性和性能。夹具覆盖蓝到紫、黄到棕、不成比例的色系强度，以及蓝/紫、黄/绿和红/橙区分度。输出在作者接受之前保持为候选。
- **FR9 — 已接受映射是显式、可检查且一致的。** 接纳已接受色板/主题集成的现行权威必须定义稳定的语义角色引用或等效的确定性创作时映射契约。一旦编辑或重新生成的色板被显式接受，映射到它的每个角色必须一致更新，无需作者手动重新复制无关值。工具可以建议映射，但单独的显式应用操作必须显示目标和补丁、保留作者编辑，并允许调整或拒绝。本需求不选择最终的 `DefineThemeInput`、编译器或构建产物形态。
- **FR10 — 重新生成绝不隐式重新着色主题。** 生成新候选不得替换已采纳色板或改变已保存主题值、归一化 token、CSS、构建的运行时模块或挂载行为。已提交的色板编辑可以有意改变显式引用它的主题映射；该源码差异及其渲染影响必须一起审查。
- **FR11 — 校验与构造分离。** 色板检查在主题包测试、内部测试工具或显式接受的未来 CLI 检查器中使用 `validate*` 或 `check*` 角色。仅校验数据和辅助函数必须留在 Core 运行时主题输入和输出之外。
- **FR12 — 无障碍是上下文相关的。** 工具可以报告显式配对的测量属性和对比度。它们不得将孤立的色板、色系、色阶或建议标记为无障碍。主题证据命名精确的前景、背景、文本大小、组件状态、模式和非颜色线索。
- **FR13 — 创作没有运行时成本。** 生成器代码、颜色数学依赖、候选、可复现性数据和建议逻辑不得进入 Core 组件运行时、主题挂载、默认主题 CSS 或 JavaScript，或主题包的默认运行时导出。
- **FR14 — 受支持的生成接口保持狭窄。** `generateTonalPalette(request)` 是纯创作函数，返回候选数据，不读写文件。`astryx theme palette generate <config>` 是其非交互式文件适配器。TypeScript 是主要的已提交输出，以便精确色系和色阶键保持可检查；JSON 可以请求用于互操作工具。这些接口不得重写主题或隐式执行语义映射。未来显式的一等色板输入、稳定映射契约或编译器集成需要单独的现行权威；本需求既不批准也不禁止。
- **FR15 — 视觉审查使用一个标准构建产物。** CLI 可以显式从相同候选数据写入自包含 HTML 预览。预览必须标识自身为 `palette-preview-v1`，显示每个生成的色系、模式、色阶和十六进制值，且不需要网络资源。它不得做出无障碍声明。它遵循与色板输出相同的覆盖保护，且未经单独显式操作不得打开浏览器。
- **FR16 — 创作指导保留意图。** 面向 Agent 的文档和评估夹具必须区分精确、有界和灵活锚点；保留显式小数和自定义布局；未请求强调色时省略；并询问模糊的强调色是一个主题值还是亮色和暗色色系，而非猜测。
- **FR17 — 新创作使用色板；旧版扩展保持兼容。** 主题创作接口不得将一个强调色输入呈现为孤立编辑，当它同时替换中性、表面、文本、边框或其他派生值时。Playground 必须移除 `Create from accent`，并保留显式颜色 token 的直接编辑。CLI 主题文档和生成的主题模板必须为新创作推荐受支持的色板工作流。在替换优先补丁中，显式参考文档必须将 `DefineThemeInput.color`、`ThemeAdaptationValue.color` 和 `expandColorScale()` 标识为已弃用的旧版创作 API，同时为未迁移主题准确记录其现有行为。`ColorScaleConfig` 和 `ColorScaleTokens` 在此生命周期内保持稳定公共类型；本记录不安排移除它们。
- **FR18 — 色阶弃用是静态的、替换优先的且无损的。** 在替换优先补丁之前，所有三个接口保持 `stable`，没有声明或警告将其标记为已弃用。该补丁必须同时发布可用的色板替代方案、稳定的版本化说明、精确的现代化命令、维护源码迁移、声明 `@deprecated` 元数据，以及创作/构建诊断。每个诊断必须命名适用的 `DEP-*` id、精确替代方案、稳定说明和迁移命令。弃用不得添加运行时兼容标志、运行时分支、渲染应用警告或可执行生产包字节。对于未迁移源码，现有 token 值字符串（包括 CSS 引用）、归一化、适配层、继承、生成的 CSS、构建和挂载行为在弃用窗口内保持字节等价。可预览且幂等的迁移遵循 `spec:AST-040`，保留这些可观察项作为基线，并报告动态、继承、带适配或其他不确定情况而不重写它们，除非能证明替代方案保留相同行为。迁移绝不调用色板生成器：它将精确的当前 token 值字符串写为导入的、主题自有的色板数据或字面 token 值，并通过 `tokens` 引用它们。移除需要下表中单独的清理 id 和次版本发布批准。

## 弃用生命周期

三个旧版接口遵循 `spec:AST-017` FR28–FR31 和 FR29a–FR29d。它们共享一个创作机制，但是不同的公共契约，因此各自单独描述和移除。它们的直接权威是 `spec:AST-008/FR18`。

### `DefineThemeInput.color`

- **包 / 接口：** `@astryxdesign/core` 类型字段。
- **弃用 / 清理：** `DEP-AST-008-COLOR-INPUT` / `CLN-AST-008-COLOR-INPUT`。
- **旧契约：** `color` 种子在 `defineTheme()` 归一化期间派生广泛的主题 token 值，并保持可被后代主题继承。
- **替代方案：** `astryx theme palette generate` 生成经审查的、主题自有的 TypeScript 色板数据；AST-040 codemod 也可以将精确的现有 token 值字符串导入为等效色板数据。主题通过引用该已提交数据的现有 `tokens` 条目写入语义角色。后续现行权威可以用一等集成替换此创作投影。
- **警告：** `@deprecated` 加上精确源码主题构建或校验诊断，每个诊断命名弃用 id、稳定的版本化说明和 `astryx upgrade --from <installed-version> --apply`。
- **迁移 / 证明：** AST-040 codemod 物化字节相等的 token 值字符串（包括 CSS 引用），并证明等效的归一化 token、生成的 CSS、适配层、继承和扩展行为。它报告并保持其无法证明的动态或可继承用法不变。
- **状态 / 目标：** 在替换优先补丁发布前为 `stable`，之后为 `deprecated`；清理未安排，需要在冻结的次版本计划中指定精确清理 id。
- **回滚：** 清理前，回滚迁移补丁或保留已弃用字段；清理后，兼容恢复补丁恢复该字段及其字节等价归一化。

### `ThemeAdaptationValue.color`

- **包 / 接口：** `@astryxdesign/core` 嵌套类型字段。
- **弃用 / 清理：** `DEP-AST-008-ADAPTATION-COLOR` / `CLN-AST-008-ADAPTATION-COLOR`。
- **旧契约：** 适配规则提供部分色阶配置，从有效根颜色轴完成。
- **替代方案：** 适配规则通过引用相同已提交主题自有色板数据的现有 `value.tokens` 条目写入条件特定的语义角色。
- **警告：** `@deprecated` 加上携带相同说明和迁移字段的精确源码主题校验诊断。
- **迁移 / 证明：** AST-040 codemod 保留每个降级适配 token 字符串和规则顺序。它报告并保持部分、继承或动态规则不变，除非能证明等效完成和 CSS。
- **状态 / 目标：** 在替换优先补丁发布前为 `stable`，之后为 `deprecated`；清理未安排，独立于根字段清理。
- **回滚：** 清理前，保留或恢复已弃用字段；清理后，兼容恢复补丁恢复其完成和降级行为。

### `expandColorScale()`

- **包 / 接口：** `@astryxdesign/core` 函数导出。
- **弃用 / 清理：** `DEP-AST-008-EXPAND-COLOR-SCALE` / `CLN-AST-008-EXPAND-COLOR-SCALE`。
- **旧契约：** 公共创作辅助函数将 `ColorScaleConfig` 扩展为广泛的 token 覆盖，包括实时 CSS 引用。
- **替代方案：** AST-040 codemod 将精确返回的 token 映射内联为已提交的 TypeScript 模块，其字符串被直接导入，或将主题调用点迁移到由该已提交数据支持的现有 `tokens` / 适配 `value.tokens` 引用。
- **警告：** `@deprecated` 加上携带相同说明和迁移字段的精确源码创作或构建诊断。
- **迁移 / 证明：** 当调用可静态解析时，AST-040 codemod 物化字节相等的返回 token 字符串。动态调用被报告并保持不变。比较旧辅助函数
