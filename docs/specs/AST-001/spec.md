# 异步选项源状态

## 意图

使用 Selector 或 MultiSelector 的人应当能使用调用方提供的所有选项，包括字段值正在解析或保存期间。当没有可用选项时，控件应传达选项源仍在等待还是已完成且为空，而不是呈现一个看似可操作、实则静默的 Selector。

## 非目标

- 重新定义输入族的 `isLoading`；它仍是值解析或保存状态。
- 为初始选项源等待状态选择公共 API 的名称或形态。
- 定义失败、重试、分页、缓存或过期响应排序。
- 更改 Typeahead 由组件自有的异步搜索生命周期。
- 在本规范 Pull Request 中实现 Selector 或 MultiSelector 的行为。

## 需求

- **FR1 — 提供的选项决定可用性。** 传给 Selector 或 MultiSelector 的规范化选项，是决定哪些选项可渲染、可选择的数据来源。
- **FR2 — 输入加载不得抑制选项。** 输入 `isLoading` 不得隐藏、禁用或以其他方式使已提供的选项不可用。字段值忙碌期间，搜索和键盘导航必须在同一组已提供选项上运行。
- **FR3 — 零提供选项即无可选选项状态。** 当规范化后的已提供选项集合中没有任何可选选项时，Selector 不得提供暗示存在可选项的激活或导航行为。
- **FR4 — 初始等待必须显式。** 初始选项源等待状态必须独立提供，不得从零选项或输入 `isLoading` 推断。
- **FR5 — 等待不得产生虚假的空或只读声明。** 在零提供选项时，显式初始等待仍无可选选项，但必须呈现并播报为加载中，而非已完成且为空或只读。在已提供选项时，等待源信号不得覆盖 FR1 或 FR2。
- **FR6 — 已完成且为空是只读且显式的。** 在零提供选项且无显式初始等待状态时，Selector 为只读且无可选选项。其可见状态和程序化状态必须传达该完成状态，且无需用户激活不可用的弹层。
- **FR7 — 加载、只读和空必须保持可区分。** 对于初始等待、已完成且为空、以及输入 `isLoading` 为 true 时的已提供选项，视觉输出、无障碍语义、焦点行为和播报必须一致。从初始等待到已完成且为空的转换必须播报一次新结果，且不得丢失控件的无障碍名称或当前值。

### 平台支持

- 支持的功能/引擎下限：与 Selector 和 MultiSelector 相同的浏览器和辅助技术支持。
- 不支持的行为：输入 `isLoading` 不得用作选项源信号的兜底。
- 浏览器证据：加载、只读和已完成且为空状态需要真实浏览器的键盘和无障碍树验证；仅 DOM 断言不足。屏幕阅读器观察建议作为 `spec:AST-009` 下的后续工作，而非合并或发布要求。

## 当前状态影响

- Selector 和 MultiSelector 在输入 `isLoading` 为 true 时，已能保持非空已提供选项的渲染、键盘可达和可选择。这满足 FR1 和 FR2；实现必须保留该行为。
- 输入 `isLoading` 当前会抑制空和无结果呈现以及搜索结果计数播报。源码注释和消费者 API 文本将该抑制描述为“选项尚未到达”，尽管该标志实际负责值解析或保存。
- 两个组件均未暴露显式的初始选项源等待状态。在零选项且无输入加载时，二者仍提供可操作的触发器，打开的是已完成且为空的内容，而非只读的无选择状态。
- `family:input-fields/FR5` 和 `family:input-fields/DEC-2` 已记录输入 `isLoading` 的已批准含义。本规范收窄了由此产生的零选项、等待和无障碍要求，适用于 Selector。
- `architecture:public-component-api` 和 `spec:AST-002` 管辖表示显式初始等待状态所需的未定公共 API。
- 实现目标是等待 API、零选项只读行为和无障碍状态转换。同时移除错误的“选项未到达”声明，并保留已填充选项的可用性。随后，所属组件契约和消费者文档必须链接适用的 AST-001 决策；在此之前，`component:Selector` 仍是已发布 Selector 行为的唯一事实来源。

## 决策日志

### DEC-1 — 输入值加载期间已提供选项保持可用

**引用：** `spec:AST-001/DEC-1`
**决策者：** `cixzhang`，`2026-08-31`

Selector 和 MultiSelector 从调用方提供的选项推导选项可用性。输入 `isLoading` 描述值解析或保存，不抑制这些选项。

已否决：将输入 `isLoading` 视为独立提供的选项尚未到达的证据，因为这会使有效选择不可用，并混淆两个无关状态。

### DEC-2 — 零选项是无选择状态，而非等待工作的证据

**引用：** `spec:AST-001/DEC-2`
**决策者：** `cixzhang`，`2026-08-31`

零提供选项意味着没有可选选项；一旦源不再显式等待，Selector 即为只读并传达已完成且为空。初始等待是独立的显式状态：它没有可选选项，但传达加载中，且不得从空数组推断。

已否决：用一次零选项观察同时表示“仍在加载”和“已完成且无选择”，因为用户和辅助技术无法区分等待与已完成的只读控件。

## 开放问题

- **OQ1 — 什么公共 API 表示 Selector 和 MultiSelector 的显式初始选项源等待？**（`human-api`）该 API 必须区分等待与已完成且为空，且不改变输入 `isLoading`，也不覆盖已提供选项的可用性。
