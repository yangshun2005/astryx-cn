# 动画布局系统规范

```json
{
  "paths": ["packages/core/src/**"]
}
```

<!-- 描述系统，而非项目：用现在时，说明它做什么。记录中不写提案、历史、Pull Request 或研究；参见 docs/contributing/spec-writing.md，并在 Pull Request 中报告其评分结果。 -->

## 意图

当某个区域内的元素尺寸变化时，变化的元素及其后的内容以同一个共享动效一起动画，而不是跳变；动效使用主题的曲线令牌，由主题的 `character` 和 `tempo` 定时。应用在每个区域启用一次；不启用则一切不变，除非某组件的记录规定其自身变化带动画（FR2）。

## 非目标

- 区域外的内容，以及另一个文档或 iframe 中的内容。
- 滑动的实现方式，由 `architecture:react-component-runtime` INV12 负责。

## 公开契约

```tsx
const scrollRef = useRef(null);
const animatedLayout = useAnimatedLayout({containerRef: scrollRef});
<ScrollableArea ref={scrollRef} label="Project">
  <TreeList items={items} animatedLayout={animatedLayout} />
  <p>Notes</p>
</ScrollableArea>;
```

## 需求

- **FR1 — 一个 Hook、一个句柄、一个 Prop。** `useAnimatedLayout({containerRef})` 返回不透明的 `animatedLayout` 句柄，无公开方法或字段。应用将其传给尺寸会变化的组件，通过该组件的 `animatedLayout` prop 传入；若组件是 Hook，则通过 Hook 的 `animatedLayout` 选项传入，组件据此上报每次变化。`containerRef` 指定区域；ScrollableArea 不自行注册，应用传入已给 ScrollableArea 的 ref，该 ref 到达原生滚动视口。每个采用组件的记录记录其 `animatedLayout` prop 或选项。
- **FR2 — 无句柄则一切不变。** 无句柄的组件保持原行为：变化的元素按自身记录所述展示变化，其后内容立即就位。AppShell 的内容区和 SideNav 侧栏在侧边导航折叠或展开时动画自身变化，LayoutPanel 渲染的可调整大小面板动画自身的折叠和打开，如各自记录所述（`component:AppShell` FR17、`component:SideNav` FR6、`component:Resizable` FR8、`component:LayoutPanel` FR7）。
- **FR3 — 变化后的内容在区域内滑动。** 对于持有句柄的组件上报的任何变化，例如展开项打开、内容加载、消息出现、条目插入或移除，其在区域内位移的内容从旧位置移动到新位置而非跳变：其后的兄弟元素，以及布局移动的其前兄弟元素（居中、末端对齐或 space-between 行，或 `order`），以及布局移动的自身祖先（居中列），在每个祖先层级直至区域且不超出区域。元素仅当其布局矩形变化且在区域可见部分内时才移动。哪些元素移动列于覆盖范围。位移内容可混合 Astryx 组件和普通应用元素，均无需启用。一个区域内的多个变化，无论是否嵌套，组合生效：每个元素移动一次，按其总变化量。区域不因滑动而滚动。
- **FR4 — 在主题曲线令牌上的一个共享动效。** 变化的元素播放自身动画（进入、退出或调整大小），其后内容随之移动。两者播放同一动效，因此定时集中控制，绝不按组件：主题的移动曲线 `--ease-move`，时长 `--duration-medium`，遵循主题的 `character` 和 `tempo`（`spec:AST-108` FR1、FR2）。滑动使用曲线令牌，绝不用弹簧，任何 character 或选项都不为其播放平台测量的曲线（`spec:AST-094` FR45）。两者在同一帧开始，Reduce Motion 同时作用于两者，如 `design:reduced-motion` DR1–DR3 要求：粗粒度主指针下为交叉淡入淡出，否则立即变化。
- **FR5 — 所有指针。** 滑动在所有指针下生效，包括鼠标：它消除了精细指针用户也能看到的布局跳变，因此属于 `spec:AST-017` FR59 下的具名精细指针变更，采用 Pull Request 须展示精细指针的前后证据。
- **FR6 — 准入。** 两个其他方面相同的页面在尺寸变化后的内容是否滑动或跳变、以及由哪个容器界定上不同，这只有调用方知道（`spec:AST-002` FR1、FR5）。句柄是配置，不是渲染槽位；无其他 API 承担此职责；它不是视觉布尔值。
- **FR7 — 文档。** Hook 的文档写明："返回一个句柄，传给尺寸会变化的组件，如 TreeList 或 Collapsible。当该组件尺寸变化时，它及其后在 `containerRef` 内的内容以同一共享动效一起动画，遵循主题的动效令牌和 tempo。固定和粘性元素保持原位，滑动绝不滚动区域，且尊重 Reduce Motion。"
- **FR8 — 两个元素可原地交换。** 区域可将一个元素原地替换为另一个，例如用骨架屏替换其内容：两者重叠使区域不为空，短暂的显示延迟防止快速加载时闪现第一个，方向承载前进或后退的页面切换。交换共享 FR4 的一个动效。在减少动效下遵循 `design:reduced-motion` DR1–DR3：粗粒度主指针下仅透明度交叉淡入淡出，否则立即变化。层退出保留在层运行时的退出副本中（`architecture:layer-runtime` INV14）。交换还可将区域旧内容作为一个临时副本保留，惰性且对辅助技术隐藏，同时新内容进入，交换结束时移除（`architecture:component-style-authoring` INV7）；AppShell 的内容区在侧边导航折叠或展开时如此（`component:AppShell` FR17），SideNav 侧栏在折叠或展开时保留其旧状态（`component:SideNav` FR6）。交换是内部的；Hook 的公开契约不变。

- **FR9 — 一个共享边缘揭示。** 区域可从其某条边缘揭示或隐藏元素：默认块末端边缘，或块起始、行内起始或行内末端边缘，例如内容旁折叠的面板。揭示在变化前后测量元素盒子，如 FR3 测量任何变化，元素的移动边缘及该边缘侧的内容以 FR4 的一个动效移动，无论该内容在元素之后还是之前（末端面板的 LayoutContent 在面板之前），因此边缘旁的内容随之滑动且不出现间隙。在块边缘形式中，元素自身的子元素在该动效下于其内容盒处静止裁剪下滑动，裁剪位于其部件进入的一侧，因此它们在移动边缘处进入和离开；自身有文本的元素、平移无法移动的子元素、或自身绘制盒子或生成盒子的元素，保留随边缘移动的裁剪。可选的双状态形式将元素旧状态如 FR8 的交换那样保留，同时元素随其移动边缘旁内容的滑动而移动；从显示状态反转时从当前位置开始。在 Reduce Motion 下，粗粒度主指针遵循 `design:reduced-motion` DR2，否则 DR3。Core 中的每个边缘揭示都是这一个：
  - Collapsible、TreeList 和 Table 的行展开保留其块末端形式（`component:Collapsible`、`component:TreeList`、`component:Table` FR15）。
  - SideNav 侧栏以双状态形式按行内边缘隐藏和揭示，自身仅保留标签和图标淡入淡出（`component:SideNav` FR6）。
  - LayoutPanel 渲染的可调整大小面板每次折叠或打开时，按面向其 ResizeHandle 的边缘隐藏和揭示，其旁的 LayoutContent 以同一动效移动（`component:Resizable` FR8、`component:LayoutPanel` FR7）。越过折叠阈值的拖动播放隐藏；重新打开已折叠面板的拖动不播放任何动效，因为指针驱动边缘。调用方仅按 `useResizable` 的尺寸渲染的面板不显示揭示，因为 Core 从不持有该元素；给定配置对象形式（`useResizable` 未返回的手工构建 `ResizableProps` 对象）的 LayoutPanel 亦然；通过 `resizable` 传入的 Hook 自身 `props` 会滑动。

  当 LayoutPanel 渲染的可调整大小面板折叠且焦点在其中时，焦点移至其 ResizeHandle（重新打开它的控件），折叠面板在打开前惰性且对辅助技术隐藏，适用于任何调整大小控制器（`component:LayoutPanel` AR2）；打开不移动焦点。此焦点规则仅覆盖折叠面板：SideNav 侧栏遵循自身记录，Collapsible、TreeList 和 Table 的行展开保持其记录的行为。边缘揭示是内部的：`useAnimatedLayout` 的公开契约不变，不新增 prop 或选项。

- 区域外的内容，以及另一个文档或 iframe 中的内容；

- 由 `order` 或 grid 放置（`grid-row`、`grid-column`、命名区域或密集打包）从区域可见部分加一个视口（或变化尺寸，若更大）之外按文档顺序带入视图的项，遍历不会到达。

## 当前状态影响

- 尚无 Core 组件采用 `animatedLayout`；TreeList、Collapsible 和 Table 的行展开（`component:Table` FR15）是首批采用者，其文档增加 `animatedLayout` 句柄。
- Core 增加 `useAnimatedLayout` 导出及其文档（FR7）。
- `architecture:react-component-runtime` INV12 产生滑动。
- `architecture:react-component-runtime` INV12 还增加原地交换（FR8）；尚无组件交换。
- INV12 还产生边缘揭示（FR9）。SideNav 侧栏的裁剪和随动从 SideNav 自身代码移入其中，可调整大小的 LayoutPanel 的折叠和打开（目前为跳变）采用它；LayoutPanel 的文档说明折叠会滑动。
- 每个移动可命中测试元素 `translate` 的运行中滑动都向 `motion/presentation.ts` 报告，如动画器的移动那样。惰性副本或关闭元素不报告。因此在 iOS WebKit 上，手势宿主处理的触摸会到达手指下绘制的内容（`spec:AST-094` FR11、FR19）。实现缺口：在 iOS WebKit 上，无手势处理的普通点击，在滑动中的元素上，仍会到达滑动前该位置的内容，直到滑动结束（滑动最长持续主题的移动时长）。

## 决策日志

### DEC-1 — 每个区域一个启用句柄；变化后的内容
