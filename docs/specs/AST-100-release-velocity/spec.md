## 意图

当用户轻扫一个面板、一个 Toast、一行、一页或一个滚轮并抬起手指时，该类型的所有 Core 和 Lab 组件都从这一动作中读取相同的速度，与 iOS 一致；抬起前已停住的手指绝不算作轻扫。组件共享对轻扫的读取；每个组件按自身阈值决定该速度的作用。一个释放过滤器定义所有组件读取的速度；组件只决定给定速度对自身的含义。

## 非目标

- 组件如何使用速度：其轻扫阈值、提交点、投影和稳定曲线仍归组件及其记录所有。
- 捏合缩放速度和浏览器自有的滚动物理。
- 公开 API：速度来源、其过滤器取值及所有阈值均保持内部（`spec:AST-002` FR3），但 `spec:AST-107` 吸附点拖拽的公开 `flickThreshold` 除外（FR3）。
- 满足本契约的等效内部实现仍然有效。

## 需求

- **FR1 — 每类表面一个速度。** 每个读取指针手势速度的 Core 和 Lab 组件都在每个物理轴上以 CSS 像素每秒报告该速度，同类型组件对同一接触动作报告相同速度。拖拽表面包括面板拖拽、Toast 滑动、行滑动、导航弹出和交互式关闭；滚动表面包括分页和滚轮选择器。`architecture:interaction-modality` INV10 负责 Core 中的来源以及 Lab 组件如何与之匹配。
- **FR2 — 移动的手指读取结果与 iOS 一致；静止的手指绝不触发轻扫。** 接触抬起时组件读取的速度，是 iOS 对同一动作报告的速度：拖拽表面取平移速度，滚动表面取滚动视图的释放速度。若接触在抬起前静止超过固定静止间隔，则为 0，这是与 iOS 唯一的差异。同类型每个组件读取相同的释放速度，且不读取其他估算值。静止间隔是内部调优值；速度如何计算由 `architecture:interaction-modality` INV10 负责。
- **FR3 — 阈值建立在单一速度之上。** 组件的轻扫、甩动或提交阈值比较 FR2 速度，可能结合组件自有的位移或投影。阈值是保持内部的按组件调优（`spec:AST-002` FR3），但产品传给 `spec:AST-107` 吸附点拖拽的公开 `flickThreshold` 除外；组件绝不派生第二个速度用于比较。
- **FR4 — 每个指针都使用事件时间。** 速度遵循输入事件自身的时间戳，因此运行延迟的处理函数不会改变它；触摸、笔和鼠标指针的同一动作给出相同速度。
- **FR5 — 方向遵循渲染方向。** 朝逻辑末端的轻扫在双向模式下都朝逻辑末端移动（`design:bidirectionality` DR13）；组件根据渲染方向将物理速度映射到其逻辑轴（`architecture:internationalization` INV11）。

### 平台支持

- 支持的功能/引擎下限：包支持的浏览器（`spec:AST-013` FR1、FR3）；带事件时间戳的指针事件。
- 不支持的行为：移动样本少于两个的手势，其释放速度为 0。
- 浏览器证据：FR4 依赖浏览器为指针事件添加的时间戳，因此需要 Safari on iOS 和 Chrome on Android 的真实浏览器证据（`spec:AST-013` FR10）；验证中的单元测试和组件测试证明 FR1–FR3 和 FR5，每个组件的真机手感仍由该组件自身提供证据。

## 当前状态影响

- `main` 上 Core 中不存在速度来源。其首次落地满足 FR1–FR5 和 `architecture:interaction-modality` INV10：iOS 的混合方式加上 FR2 的静止重置，且无可选替代过滤器。Lab 手势按 INV10 所述与之匹配。
- BottomSheet 的拖拽通过其近期样本上带事件时间戳的两点窗口估算速度。在 FR1 和 FR2 下，它读取跟踪器。
- Item 的行滑动比较以处理函数时钟计时的像素每毫秒速度。在 FR1、FR2 和 FR4 下，它读取以像素每秒计、带事件时间戳的跟踪器，并保留自身阈值（FR3）。
- Toast 的滑动以挂钟时间对整段拖拽的位移取平均。在 FR1、FR2 和 FR4 下，它读取跟踪器，并保留自身阈值（FR3）。
- 之后读取手势速度的组件，如分页、滚轮选择器、导航弹出或交互式关闭，都从跟踪器读取。

## 决策日志

### DEC-1 — 一个与 iOS 读取一致的释放过滤器，带静止重置；阈值仍按组件

**引用：** `spec:AST-100/DEC-1`
**决策者：** `cixzhang`，`2026-10-24`

每个组件各自估算速度，会导致同类型组件对同一次轻扫读取不同速度，且抬起前停顿的手指在一处算作轻扫、在另一处不算。一个释放过滤器，Core 中一个来源、Lab 中无副本，让同类型每个组件对同一动作得到相同速度。按 iOS 方式读取移动的手指，使轻扫、分页和关闭在其阈值附近的表现接近 iPhone；静止重置阻止静止手指触发甩动，这是过滤器与 iOS 唯一的差异。速度的含义仍作为内部调优归各组件所有，因此组件保留自身手感而无需第二个估算器。

已否决：固定时间窗口，会把快速轻扫读得比 iOS 快得多；iOS 的混合方式但不带静止重置，会在停顿后甩动；以及多个可选估算器或按组件过滤器，会重新引入本记录所消除的分歧。
