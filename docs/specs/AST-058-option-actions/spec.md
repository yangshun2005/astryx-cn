## 意图

选择器的组合框打开一个选项弹出面板。有时该打开面板中的某个选项在其首要动词旁携带第二个动词：可编辑的已保存标签、可重命名的已保存搜索、可移除的最近值。用户需要按下该控件而不选中选项，屏幕阅读器用户需要知道它存在并到达它。

Astryx 的选择器无法承载它。每个选项槽位都渲染在选项的点击目标内，因此放在那里的控件会同时触发并切换，且 `role="listbox"` 仅允许 `option` 和 `group` 子元素，因此该控件无论落在何处都无效。构建者要么放弃该动词，要么重建列表。

本记录给出一个答案：**选项以调用方渲染的一个节点携带其操作，持有任何此类选项的弹出面板是一个网格，其行将选项与其操作配对。** 操作位于打开弹出面板内选项旁；此处不涉及折叠触发器，其自身控件（清除、箭头、状态）保持当前契约。组合框契约得以保留，键盘路径无需第二界面即可存在，且无调用方为无操作的行编写守卫代码。

## 所有权边界

**拥有**

- 选项的次要控件以调用方渲染的一个节点携带于选项上，以及该键在弹出面板渲染所依据的每套选项词汇表中的名称和类型。
- 持有带操作选项的弹出面板是一个网格、其行如何构成，以及弹出面板何时切换。
- 指针、手指、键盘和辅助技术如何到达操作，以及到达它绝不改变选中状态。
- 该安排保持的可访问性底线：有效的树、具名控件、一个 Tab 停靠点、无仅悬停路径。
- 哪些组件采用，以及渲染该词汇表但未采用的宿主如何表现。

**为何无现有记录可承载它**

- `spec:AST-057` 拥有一种触摸手势，用于加速宿主已显示的动词。其 FR9 和 DEC-4 保持 `Item` 不变，并按其自身文本将 `option` 行排除在其 `reveal` 模型之外。本记录是选择控件中的始终可见控件——AST-057 假定存在但未定义的界面。
- `component:Selector` 为 `current`，`component:MultiSelector` 为 `draft`；`SelectorOptionData` 是两者共享的一个类型，其上的键不属于任何一方单独所有（`architecture:knowledge-contracts` INV2）。`component:MultiSelector` 关于逐行操作的草案主张（其 FR9 / DEC-2）被撤回，以本记录为准。
- `component:BaseTypeahead`、`component:Typeahead` 和 `component:Tokenizer` 为 `draft`，从 `SearchableItem`（第二套词汇表）渲染。一条规则跨五个组件绑定两套词汇表是系统事实，而非组件事实。
- [`spec:AST-056`](../AST-056/spec.md) 为 `current`，拥有类型化查询状态的词汇表。它治理相同的面板，并在此被引用——空状态的播报（AR1）和创建行（DEC-3）共享该面板——但次要控件不是搜索状态，且 `current` 记录不能携带未批准的主张（`architecture:knowledge-contracts` INV1、INV14）。
- [`architecture:public-component-api`](../../architecture/public-component-api.md) 持有共享命名语法，并通过 `deciding_specs` 链接其裁决；新的跨组件裁决应属于它所链接的规范。
- [`family:input-fields`](../../families/input-fields.md) 拥有字段外观。`BaseTypeahead` 不是成员，且面板不是外观。

## 非目标

- **在一个单元格内的多个控件之间移动。** 单元格持有一个节点（FR1、DEC-3），因此无需在其内遍历焦点的规则。有多个动词的调用方在节点中放置一个菜单触发器；其打开的弹出面板拥有自己的键盘模型。若后续记录允许单元格内有多个控件，仓库自身的树遍历焦点先例是其起点。
- **悬停显示、滑动显示或触摸手势的对应物。** 操作在每种输入下静止时可见。行上的触摸手势属于 `spec:AST-057`。
- **`CommandPalette`。** 其行为复合子元素（`CommandPaletteItem`），且其内部将 `SearchableItem` 转换为 `SelectorOptionData` 仅携带 `value` 和 `label`，因此两个声明点都无法到达其渲染的行。采用它是在 `spec:AST-002` 下的独立准入。
- **`ComplexSelector`。** 其内容为调用方拥有的标记，无列表框角色；那里的调用方已渲染带控件的行。
- **操作单元格的主题目标。** 是否允许一个由各组件自己的主题记录决定。
- **折叠触发器上的控件。** 清除按钮、箭头、状态图标或调用方围绕关闭控件组合的任何其他内容都不是选项操作，不在此治理。
- **操作的处理程序语义。** 编辑做什么——打开对话框、就地修改——是调用方的事。面板不会因操作触发而关闭或重新过滤；处理程序可以。操作触发后行是否离开是滑动问题，留在 `spec:AST-057`；选择器选项不会因有人按下编辑而消失。
- 等效的内部实现只要满足本契约即保持有效。内部模块、文件、函数名、算法、数据结构、存储布局、清单、日志、锁、事务协议以及 CI 作业/工作流拓扑属于架构或实现，除非调用方或互操作系统有意依赖该确切机制作为公共协议。

| --------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | -------------- | --------- |
| `SelectorOptionData.action` | `ReactNode \| undefined`                                                                | 选项的次要控件，在 `Selector` 和 `MultiSelector` 中：调用方渲染并命名的一个节点；宿主放置它。缺失和 `null` 含义相同：无。 | 缺失  | `spec:AST-058` | 提议  |

操作单元格是每个采用者选项解剖中命名的部件：调用方用组件填充的渲染内容槽位（`architecture:public-component-api` INV18）。

## 需求

### 行为契约

| ID  | 不变量                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 依据                                                                                                         | 验证状态                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| FR1 | 选项以 `action?: ReactNode`（一个节点）携带其次要控件。该键在 `SelectorOptionData` 和 `SearchableItem` 上名称相同、类型相同。调用方渲染控件并拥有其名称、处理程序、禁用状态和外观；有多个动词的调用方渲染一个菜单触发器，其弹出面板拥有其余部分。宿主在 FR3 所述位置渲染该节点，且不得检查、克隆或包装它以做出任何决定；检查其是否存在（FR2）不算检查。不存在宿主自有的操作类型或组件。 | DEC-1、DEC-3、DEC-4；`SideNavItem.actions`、`Item.endContent`；`architecture:public-component-api` INV2、INV3 | 提议；`main` 上无证据                      |
| FR2 | 弹出面板在任一次渲染中，若任一已声明选项——在节的任意深度、在任何查询过滤它之前——携带非 `null` 或 `undefined` 的 `action`，则从该次渲染起为网格，并在组件挂载期间保持网格；在此之前为列表框。拥有弹出面板的控件通过 `aria-haspopup` 声明生效角色（`grid`；底部面板保持 `dialog`）。角色跟随过滤视图或切回的弹出面板是缺陷。                                                                                                 | DEC-2、DEC-5；`spec:AST-002` FR8、FR15                                                                        | 提议                                             |
| FR3 | 在网格中，每个选项是一个 `role="row"`，携带选项的 id、`aria-selected` 和 `aria-disabled`，每行恰好两个 `gridcell` 子元素：第一个持有选项今天渲染的一切——选择标记或复选框、图标、标签、描述、`renderOption` 输出——第二个持有其 `action` 节点，未声明时为空。组件生成的行（全选、创建行）是相同形状的行，操作单元格为空。没有行有一个或三个单元格。                                                                | DEC-2、DEC-3；`useGridFocus` 固定列                                                                    | 提议                                             |
| FR4 | 激活操作仅运行调用方自己的处理程序：选中状态不变，高亮行不因其改变，面板既不关闭也不重新过滤。按下选项单元格的选中或切换与今天完全一致。选项的 `disabled` 仅治理其选中；操作是否禁用是调用方控件自身的状态，宿主不读取它。
