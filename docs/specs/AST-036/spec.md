# 通用 Markdown 插件系统规范

## 契约概览

| 领域         | 契约                                                                                                                                                                                                                                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公共契约     | 一个增量式 `plugins` prop 和 `createMarkdownPlugin()`。插件只暴露 `syntax`、不可变 `transform` 和 `renderers`。文本匹配、语义围栏和源码装饰是由辅助函数编写的 transform，不是独立的协议阶段。                                                                                                |
| 行为         | 解析、转换、Markdown 渲染和 Outline 观察同一棵稳定、严格类型化、对齐 MDAST 的树。有序 transform 返回经过校验的替换树，同时 Core 保留内置语义和可读回退。                                                                                                                  |
| Remark 兼容性 | 独立适配器可在文档化的受支持 MDAST 子集上运行同步、仅含 transform 的 Remark 插件。解析器扩展、异步插件、编译器插件、任意 `VFile` 状态和不支持的节点类型一律拒绝，不做近似处理。                                                                                      |
| 最终用户影响 | 读者可能获得额外语法和转换后的文档结构，同时普通 Markdown、可复制回退、标题与 Outline 身份、无障碍、导航、图片、列表和表格仍由规范所有者掌控。                                                                                                                  |
| 构建者影响   | 现有构建者无需改动。选择启用的构建者传入一个稳定的插件列表。简单文本、围栏和装饰用例使用返回 transform 的辅助函数。                                                                                                                                                          |
| 兼容性       | 省略插件与 `plugins={[]}` 在语义上是同一个空流水线。Core 可跳过空准备和分配，但不存在独立的行为模型。现有 `components`、`inlinePlugins`、数学、引用、自动链接和解析器签名保持原义。                                                                  |
| 审查检查     | 拒绝第二个插件 prop、公开的生命周期专属阶段、可变共享 AST、原始标记节点、插件覆盖 Core 语义、无界解析器钩子、静默的 Remark 不兼容、transform 驱动的重新解析，或对每个源字符执行与每个插件成正比的工作。                                                           |

本节是审查投影；以下正文为准。

## 意图

应用作者应能添加可复用的 Markdown 行为，而无需重写源文本、Fork 解析器或替换整个渲染器。一个易于理解的模型必须覆盖新源语法、文档级语义转换和类型化渲染。

公共概念应少于用例数量。散文替换、语义代码围栏、源码装饰、标注块、frontmatter、目录、脚注和兼容的 Remark transform 都使用同一个不可变 transform 边界，而不是成为独立的协议阶段。

## 所有权边界

AST-036 拥有共享插件准入、语法与 transform 排序、兼容性、校验、失败行为、解析身份、Remark 适配器限制和可观察资源约束。Markdown 拥有其具体 AST 声明、解析器集成、聚合渲染和辅助函数。Outline 拥有其对 Markdown 标题身份的投影。第一方插件在其自身模块记录中拥有其特定语义和证据。

## 非目标

- 将 Unified、可变 MDAST、`VFile` 或 Remark 作为 Core 运行时依赖。
- 在另行批准的迁移之前破坏已发布的 `parseMarkdown` 结果形状。
- 承诺与任意 Remark 解析器、transform、编译器、异步或原始 HTML 插件兼容。
- 暴露可变共享 AST、无限制访问器、DOM 访问、包发现或注册表。
- 替换通用 CodeBlock 高亮或 Core 拥有的文档、标题、导航、图片、列表或表格语义。
- 将零插件文档设为独立的语义模式。

## 平台支持

- **功能与引擎下限：** 与当前 Markdown/Core 包支持一致；协议不新增浏览器、React、Node 或 TypeScript 下限。
- **不支持的行为：** 不支持的语法/transform/Remark 行为会失败关闭到最后一个有效的可读文档，不能静默近似输出。
- **浏览器证据：** 交互式故事在真实 Chromium 中验证渲染输出、键盘/焦点顺序、可复制回退、导航所有权和不变的无插件行为；服务端渲染夹具覆盖非浏览器使用。

## 当前状态影响

| 当前接缝              | 保留的行为                                                                     | 新角色                                                                                                      |
| --------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `components`              | 替换受支持的内置渲染器，包括全围栏代码渲染器。          | 在插件渲染之前生效，但语义围栏提案优先认领其围栏（FR17）。            |
| `inlinePlugins`           | 以已发布的遍历、重叠、回调和错误行为替换匹配的散文。 | 保持兼容；后续迁移只能在完全对等后通过辅助函数支持的 transform 适配。 |
| 解析器和流式 API | 产生已发布的 AST 并复用已确定的增量输出。                         | 接受语法插件并应用实时 transform，但不使 transform 成为解析身份的一部分。             |
| Markdown 和 Outline      | 共享内置标题文本和 slug 行为。                         | 还共享转换后的标题投影和冲突分配。                                           |

## 语义模型

插件条目是由 Markdown 公共 `createMarkdownPlugin()` 工厂创建的不透明值，仅通过有序 `plugins` 数组接受。其公共形状为 `{name, apiVersion: 1, syntax?, transform?, renderers?}`，受以下规则约束：`syntax` 包含有序有界的内联/块分词器声明，并要求 `parseKey`；`transform` 是一个同步的不可变根到根函数；`renderers` 是以节点名称为键的映射，其条目提供一个纯渲染回调和确定性的 `toText` 投影。插件不暴露其他生命周期阶段。普通对象不能伪装成条目，异构列表在严格 TypeScript 下保留其扩展节点类型的并集。

公共构造接口为 `createMarkdownPlugin()`、`createMarkdownTextTransform()`、`createMarkdownFenceTransform()` 和 `createMarkdownSourceDecoration()`。有限的 Remark 兼容性是来自 `@astryxdesign/core/Markdown/remark` 的独立可 tree-shake 的 `createMarkdownRemarkTransform()` 导出。这些辅助函数返回或注解唯一的 `transform` 能力；它们从不接受 React 渲染回调，也不是额外的生命周期阶段。具体而言，`createMarkdownFenceTransform()` 将符合条件的内置代码节点映射到所属插件的类型化扩展数据，而该插件的标准 `renderers` 映射拥有呈现和 `toText`。详细的 TypeScript 签名和示例位于 Markdown 消费者文档中，而这些名称和职责是本契约的一部分。

规范文档是一棵不可变、可判别、Unist 形状的树，与下方受支持的 MDAST 子集对齐。**MDAST 是由 syntax-tree/unified 生态维护的公共社区规范，不是浏览器或标准机构 API。** Astryx 的公共契约是其自身导出的、版本化的 TypeScript 节点联合：在对齐处使用所列 MDAST 节点名称和字段含义，记录每一处偏差，并且不承诺与任意 `mdast`、Unified 或第三方插件版本在名义或结构上可互换。`parseMarkdownAst()` 和 `parseInlineAst()` 从服务端安全的 `@astryxdesign/core/Markdown/parser` 子路径增量暴露该树；组件 barrel 也为客户端代码重新导出它们。解析、transform、Markdown 渲染和 Outline 投影观察相同的节点含义。已发布的解析器入口点通过兼容边界保留当前结果类型和值；采用插件无需迁移。

Markdown 所有者暴露稳定的节点联合和按节点类型收窄的遍历。插件定义的扩展类型增强通用联合，而不拓宽无关的内置回调。transform 接收只读输入并返回原始根或替换根。允许等效的校验和不可变性实现。

语法贡献声明非空字面前缀、有限待定边界和同步确定性分词器。它只能发出其所属的类型化扩展节点。带语法的插件声明稳定的解析身份；只有有序语法身份参与增量解析身份。

transform 是同步且确定性的。它可以在允许编辑矩阵内替换、插入、删除或注解可表示的节点。它不能修改输入、编写源码来源、引入原始标记或 React 值，或绕过 Core 拥有的语义。transform 变更刷新转换输出，但不改变语法解析身份。

渲染器仅接收类型化扩展节点数据。通过语法或 transform 引入的每个扩展节点都有渲染器和确定性的可感知文本投影。有源支持的叶子回退到精确的原始源码；合成叶子回退到其必需的文本投影；容器保留并渲染其经过校验的子节点。失败后兄弟内容继续。

每个扩展类型声明 `content: 'none' | 'phrasing' | 'flow'` 或一个有限允许列表，收窄 `display` 所暗示的类别。Core 在每个 transform 边界校验子节点。语法创建的容器声明 Core 解析的内部源码范围；插件从不将原始源码转为子节点。插件可以读取或删除另一个插件的节点，但只能创建、编辑或复制自己的节点。跨插件读取通过 `dependsOn` 声明，并对照列表顺序校验。

插件准入和每个失败阶段在开发和生产中使用一个无源码、限速的 `onPluginDiagnostic` 通道。格式错误的条目和协议版本不匹配在本地失败，而不是抛给调用方。插件编写的报告使用稳定代码，绝不使用文档派生文本。

文本匹配、语义围栏和源码装饰是可选的 transform 辅助函数，不是额外的公共阶段。允许等效的优化执行，前提是保留有序 transform 语义和可观察结果。

| 链接和图片                | 插入或更新通过其当前导航/资源所有者的值。                                 | 绕过目标、协议、替代文本或可信资源策略。                               |

| 代码围栏                     | 语义围栏辅助函数可将拥有的类型化扩展数据附加到原始代码节点。                    | 通过辅助函数替换源码、在辅助函数内渲染，或认领其未注解的围栏。  |
| 源码装饰               | 将有源支持范围附加非语义、非交互的呈现元数据。                         | 更改 AST 含义、焦点顺序、可访问名称、导航、选择或可复制文本。                 |
| 插件扩展节点          | 插入/编辑 transform 所有者的节点；读取或删除外部节点/子树；保留经过校验的子节点。 | 铸造、编辑、复制或内部重排另一个插件的节点；未声明的子内容。     |
| 内联入口点              | 返回恰好一个段落等效根，包含短语节点。                                     | 块节点、多个顶层块或更改的容器形状。                                 |

## 有限 Remark 兼容性配置

Remark 适配器接受一个同步、仅含 transform 的插件，限于上述矩阵。每次调用接收一个全新的可变树副本和一个隔离的受限文件对象。该文件暴露只读源文本、每次调用的有限 JSON 数据和诊断报告；不暴露处理器注册、跨运行状态、编译器、I/O 或异步完成。

适配器的输入类型在结构上兼容常规 Unified/Remark `Plugin` 值，包括其宽泛声明的 transformer 返回联合，因此兼容包无需类型包装。运行时接受仍然更窄：实际返回 promise 或使用不支持能力的调用会失败关闭。Astryx 导出其自身受支持子集的树和文件类型，而不是重新导出或固定完整的 `mdast`/Unified 类型表面，因此上游类型演进不能静默拓宽 Astryx 的契约。

Remark 兼容性是内容兼容，不是呈现兼容。适配的插件只能返回受支持的结构节点和字段；Astryx 仍通过其自身组件、token、导航/资源策略和无障碍语义渲染这些节点。`html`、`hName`、`hProperties`、`hChildren`、自定义编译器输出、CSS 假设和第三方渲染器约定一律拒绝，不做近似处理。需要新呈现的插件必须在 Remark 适配器之外使用 Astryx 拥有的类型化扩展节点和渲染器。

适配器在插件返回或修改的树可观察之前，对照矩阵校验它。不支持的节点、原始 HTML、promise、共享处理器状态
