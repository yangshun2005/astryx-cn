# 原生优先界面系统规范

<!-- 描述系统本身，而非项目：用现在时，说明它做什么。记录中不写提案、历史、Pull Request 或研究内容；参见 docs/contributing/spec-writing.md，并在 Pull Request 中报告其评分结果。 -->

## 意图

使用 Astryx 产品的用户，无论在哪里使用——浏览器中，还是 iOS、Android、macOS 或 Windows 上的原生应用——都应获得原生优先的体验。在每个平台上，组件的行为、响应和性能都应达到该平台在用户所运行 OS 版本上最佳软件的水准，产品也可以提供仅在某些平台上存在的体验。

每个组件都有一个共享的核心契约，保证其含义、文案、状态和无障碍性在所有平台上一致；此外每个平台还有一个平台契约，补充该平台在核心之外额外支持的 Props。开发者在 TypeScript 和各原生语言中看到的都是自己所构建平台的 Props，来自其他平台的 Prop 会报错，而不是静默无效。文档和 CLI 也展示同样的划分。

`@astryxdesign/core` 服务于 Web。`@astryxdesign/native` 服务于原生平台，且只单向读取 core，因此 Web 用户不安装任何原生内容，原生应用也不加载任何 Web 内容。团队在一个 Astryx 主题中一次性定义视觉标识；仅原生的视觉意图以持久化结果的形式书写，在平台变化时保持其含义，任何与特定平台或 OS 版本绑定的内容只写在该平台的条目内。

Astryx 通过在相同场景下将候选方案与平台自身工具包进行对比测量，来决定每个原生平台的构建方式，并且只依赖它能够维护的运行时。

## 非目标

- 各平台的发布顺序（OQ2）以及每个平台支持的 OS 版本（OQ4）。
- 确切的性能阈值（OQ1）。本记录负责定义测量什么以及如何比较方案。
- 任何平台实现的内部细节，只要它满足本契约。
- 由 Astryx 组件构建的产品模板、导航结构和应用外壳。
- 改变 Web 调用方的类型或行为。本契约隐含的 Web 移除遵循 `spec:AST-017`（FR14）。
- 满足本契约的等效内部实现仍然有效。

## 需求

- **FR1 — Astryx 面向 Web 和指定的原生平台。** Web 界面是浏览器。原生界面是原生平台 `ios`（iPhone 和 iPad）、`android`、`macos` 和 `windows` 上的应用。每个原生平台声明其支持的 OS 版本（OQ4）。原生平台只有在满足 FR11 和 FR12 时才受支持。每个组件声明其支持的平台。
- **FR2 — 每个平台以其自身能力上限为目标。** 实现可以使用其平台提供的任何能力。任何平台都不受限于其他平台能表达的内容：原生平台不受限于 Web 标记和 CSS，Web 也不受限于原生实现能绘制的内容。
- **FR3 — 组件有一个核心契约和每个平台一个契约。** 核心契约是组件的名称、提供该组件的每个平台以相同含义和默认值支持的 Props、其状态、其文案以及其无障碍语义（名称、角色、状态、焦点行为和播报）。在提供该组件的每个平台上都相同。
  - 当 Prop 的行为符合 core 已为该平台输入类型定义的行为时，该平台即支持该 Prop。`tooltip` 保留在 core 中：core 定义了在没有悬停时 tooltip 的行为（Tooltip `touchTrigger`），触屏平台按该方式行为。
  - 只有当提供该组件的平台无法匹配 core 为其输入类型定义的行为时，Prop 才离开 core。此类 Prop 属于能够支持的平台的契约（Web、iOS、macOS、Android、Windows），同一 Prop 可以以同一含义出现在多个平台契约中（FR8）。链接上的 `rel` 和 `target` 属于 Web 契约：应用平台通过系统打开每个链接，没有可设置的关系或浏览上下文。
  - 在同一语言内，一个 API 服务于该语言应用运行的所有平台，并按设备适配，正如 SwiftUI 的 `.help` 在 macOS 上显示 tooltip，在 iOS 上变为提示。只有当该语言的其他平台上不存在诚实的行为时，Prop 才限定于单一平台；此类 Prop 需说明原因，且绝不为本可适配的行为让应用按平台分支（`#if`）。
  - 平台绝不提供它不完全支持的 Prop。平台接受但忽略、或仅部分支持的 Prop 违反 `architecture:public-component-api/INV2`。
  - 平台契约绝不移除、重命名或改变核心 Prop 的含义。将已发布的 Prop 从 core 移到 Web 契约不会改变任何 Web 调用方的类型，因为 Web 类型是核心契约加 Web 契约；原生契约则不再提供它。
  - Web 契约持有 Web 基础 Props：样式输入、DOM 事件、refs、元素选择和 HTML 属性。
  - 组件可以仅存在于某些平台；在其他地方使用它会在类型检查或构建时失败，并给出指明受支持平台的错误信息，绝不渲染静默替代品。
- **FR4 — 核心契约是可移植的。** 每个核心 Prop 在受支持平台应用所用的每种语言中都有对应形式，包括 Swift 和 Kotlin：字符串、数字、布尔值、封闭字符串集、开放字符串集、布尔值与封闭字符串集的组合、字符串与布尔值的组合、数组、这些类型的记录、可选值，以及参数可移植的回调。
  - **开放字符串集**是一组内置名称，可由主题或应用扩展，如同 core 的可扩充映射。其线上值就是名称，与 Web 相同。每个原生平台为其提供的类型是字符串支撑的值，每个内置名称对应一个常量，该平台的主题构建为每个主题声明的名称添加一个常量，正如 Web 主题构建写入 TypeScript 扩充。任何名称都可解码；收到没有对应规则的名称的平台绘制组件的基础外观，正如 Web 对没有内置样式的扩充名称所做的那样。
  - **布尔值与封闭字符串集的组合**，例如 CheckboxInput `value: boolean | 'indeterminate'`，在每个平台上将 `true`、`false` 和每个命名状态保持为不同的值，其线上值与 Web 值相同。
  - **字符串与布尔值的组合**，例如 Avatar `tooltip: string | boolean`，在每个平台上将 `true`、`false` 和字符串保持为不同的值。其 Swift 类型是枚举，每个布尔值一个 case，另有一个携带字符串，例如 `AvatarTooltip`，其线上值与 Web 值相同。
  - Web 类型比这些种类更宽的 Prop 可以指定一个可移植的封闭集，包含每个平台支持的值，每个映射到一个 Web 值，例如 Button `width`：`content`（默认）或 `fill`，其中 `fill` 是 Web 的 `'100%'`。该 Prop 的其他 Web 值保留在 Web 契约中。
  - 自由形式内容（`ReactNode`）和渲染函数不可移植。它们属于 Web 契约以及实现运行 React 的任何平台契约；core 以类型化插槽表达内容。**文本**插槽是字符串。**图标**插槽是共享图标名称（FR17），每个平台按 FR17 所述解析；在原生平台上，开发构建中未知名称会停止并给出指明图标的错误信息，发布构建中则不绘制任何内容。**内容**插槽持有命名的 Astryx 组件。平台契约可以为同一插槽接受更宽的形式，例如 Web 上的 React 节点；插槽保持一种含义，core 形式是每个原生平台接受的形式。
- **FR5 — 平台 Props 是平台作用域类型。** `@astryxdesign/core` 暴露核心契约和 Web 契约；其默认类型是 Web 契约，对 Web 调用方不变。`@astryxdesign/native` 暴露原生平台契约，由消费者的类型解析条件选择：`ios`、`android`、`macos` 或 `windows`。消费者配置依赖这些条件名称，因此它们是公开的。在平台条件下，组件的 Props 是其核心契约加该平台的契约，来自其他平台契约的 Prop 是类型错误。Swift 和 Kotlin 绑定从 `@astryxdesign/native` 发布，由与 TypeScript 类型相同的契约定义生成。
- **FR6 — 面向多个原生平台的代码可以仅使用 core。** 在 `shared` 条件下，`@astryxdesign/native` 仅暴露核心契约。在多个原生平台上运行的代码可对其通过类型检查，其中的平台 Prop 是类型错误；平台 Props 位于该平台的文件中。共享代码是否必须使用此条件为 OQ5。Web 和原生代码共享的文件仅导入核心契约类型和非视觉逻辑；每个平台自己的文件导入该平台的组件（DEC-9）。
- **FR7 — 基础 Props 跨平台协调。**
  - **共享基础 Props** 在每个平台上相同：`id`，稳定标识符，以及 `isHidden`，将组件从布局和无障碍树中移除。每个平台将其映射到自己的机制，例如 Web 上的 `id` 属性和 iOS 上的无障碍标识符。
  - **平台基础 Props** 属于一个平台的契约。Web 基础 Props 是 `architecture:public-component-api` 管理的 DOM 属性。
  - **目标：** 每个组件声明其基础 Props 附加到的部分，例如其根、触发器、控件或容器，该部分在每个平台上相同。已路由基础 Props 的家族记录，例如 `family:input-fields`，为其成员决定该部分。
  - **协调：** 核心 Prop 拥有其概念。核心 Prop 拥有的概念的平台基础 Props 不属于该组件的平台契约；核心 `label` 拥有无障碍名称，因此 Web 的 `aria-label`/`aria-labelledby` 和 iOS 的无障碍标签不是单独的输入。名称被核心 Prop 使用的平台基础 Prop 从该平台的基础中移除，正如 DOM 的 `onChange` 是组件的 `onChange` 报告值的地方。这扩展了 `architecture:public-component-api/INV5`：组件拥有的无障碍和行为不能被覆盖。类型系统无法拒绝的已移除连字符属性如何强制执行，为 OQ6。
- **FR8 — Prop 名称跨平台不冲突。**
  - 平台 Prop 绝不重用核心 Prop 名称。
  - 核心 Prop 名称不是 Swift 或 Kotlin 的关键字，也不是平台工具包已用于不同含义的名称，例如 React Native 中的 `style` 或 `testID`。
  - 当组件拥有该概念时，Astryx 可以为组件 Prop 收回 Web 基础名称。每个收回的名称都需声明，该平台自身的含义从该组件的基础 Props 中移除（FR7）。`onChange`、`title`、`color` 和 `content` 目前已被收回。
  - 同一名称只能为同一概念出现在两个平台契约中，例如具有各平台自己值的 `menuStyle`。它绝不出现于合并平台的类型中，文档展示每个平台的值。
  - 不满足这些规则的 Web 契约 Prop，例如 `as`（Swift 和 Kotlin 关键字）或 `style`，保留在 Web 契约中，绝不进入 core。
- **FR9 — 文档和 CLI 感知平台。** 组件文档中的每个 Prop 都标记为核心或指明其平台，每个示例都指明其目标平台。原生平台契约由 `@astryxdesign/native` 记录。`astryx component <Name>` 显示核心契约，选择平台时显示该平台的契约。一个平台的输出绝不将另一平台的 Props 列为可用。主题文档按平台展示原生主题配置。
- **FR10 — 原生主题配置构建在已定义主题之上。** 一个 `defineTheme` 定义服务于 Web 和每个原生平台，并保持为 token 的唯一权威。Token 和主题本地 token 是共享部分，在各处含义相同（`architecture:theme-compilation/INV10`）；仅 Web 部分遵循 FR18。`@astryxdesign/native` 导出 `defineNativeTheme(theme, config)`，它接受不变的 `DefinedTheme` 并添加仅原生的视觉意图；它绝不设置或覆盖 token：
  - **持久化意图。** 成员命名人能看到的结果，绝不命名平台功能名称或 OS 版本。成员为 `material`，类型 `'opaque' | 'translucent'`；`corners`，类型 `'smooth' | 'stepped'`，其中 smooth 在圆角 token 处绘制平台自身的圆角，stepped 绘制大小为 `border-width` 的方形台阶，数量以圆角内能容纳为限，边框遵循相同台阶；`imageScaling`，类型 `'smooth' | 'pixelated'`，其中 pixelated 以最近邻缩放栅格图像；以及 `textGrid`，正整数，字体绘制所用的每 em 网格单元数，文本尺寸（包括平台的文本尺寸增长）对齐到该网格，使一个网格单元覆盖完整设备像素，绝不低于用户的文本尺寸设置。缺失的成员保持平台默认外观。每个原生平台读取持久化意图，并以所运行 OS 版本最接近的能力实现它，例如在有该能力的 iOS 版本上使用系统玻璃材质，或更早的系统模糊。没有此类能力的平台按成员缺失渲染。
  - **平台条目。** `platforms.<platform>` 使用 FR1 和 FR5 的平台名称，并持有有序条目列表。条目可以指定 OS 版本范围，`minVersion` 和可选的 `maxVersion`；没有范围的条目适用于所有受支持版本。条目持有该平台自身词汇表中的成员，例如 `ios` 的 `material: 'liquidGlass'`，以及 `components`：该平台主题目标的覆盖，包括仅存在于该平台契约中的目标，取自该平台已发布的主题目标和成员列表，因此未知目标或成员是类型错误。条目仅在其平台和范围内适用。在那里，其成员替换同名的持久化成员，后匹配的条目替换先前的条目。
  - 平台功能名称仅在其平台条目内有效，仅存在于某些 OS 版本的功能仅在范围位于其中的条目内有效。
  - 原生主题可以 `extends` 另一个：持久化成员逐成员合并，子级某平台的条目列表替换基级该平台的列表。每个值都是纯可序列化数据，已发布词汇表之外的成员是类型错误。
- **FR11 — 原生平台在每个受支持 OS 版本上都是原生优先的。** 当平台自身的控件或惯例满足其契约时，组件使用它：导航、表单、菜单、选择器、开关、文本输入、滚动、焦点、键盘快捷键、触觉反馈和系统材质。仅当平台没有时才绘制自定义控件。在每个受支持 OS 版本上，它使用该版本的控件和材质。比所运行 OS 更新的能力降级为最接近的早期平台等效项或持久化意图，绝不降级为损坏或空白状态。触摸目标满足平台最小值，文本遵循平台的文本尺寸设置。当组件按屏幕尺寸在呈现方式之间选择时，紧凑为 `spec:AST-012` FR9 以点或密度无关像素计，而非平台的尺寸类；平台自身的控件仍呈现所选界面。原生平台只有在其最旧和最新受支持 OS 版本上满足 FR12 标准时才受支持。
- **FR12 — 方案在同一评分卡上比较。** 构建原生平台的每种候选方式都以相同方式测量。候选包括基于生成契约的平台视图、React Native 组件、在驱动平台视图的 JavaScript 引擎中运行的 TypeScript 组件逻辑，以及通过原生渲染器运行的 Astryx Web React 组件：
  - **场景：** 一组共享的脚本化用户流程，覆盖代表性组件和模板，每个步骤由用户手势及其预期状态定义一次，并在每个候选和参考上原样重放。
  - **参考：** 用平台自身工具包直接构建的相同场景，例如 SwiftUI 或 UIKit、Jetpack Compose、AppKit 或 WinUI。参考设定候选评分所对照的上限。
  - **设备：** 运行发布构建的真实硬件，在每个平台最旧和最新受支持 OS 版本上，包括低端设备。
  - **捕获：** 每个场景步骤在设备上截图为屏幕截图，每个行为（例如表单打开和关闭、导航过渡、手势、滚动、按压反馈和键盘出现）为短视频，每个场景为屏幕录制。为每个候选、参考和同一场景的 Web 渲染捕获，在浅色和深色以及最大文本尺寸下。视觉和动效评分从这些捕获判断，绝不从源代码或样式值判断。
  - **体验：** 对平台惯例和核心契约（FR3）的符合度，按场景步骤判断；行为与动效，按行为视频对照参考判断时序、手势响应和可中断性。
  - **品牌保留：** 主题标识（其颜色、排版、形状、间距和图标）在屏幕保持原生优先的同时向平台传递的可识别程度，对照同一主题的 Web 渲染判断，并对捕获与主题解析值进行像素检查。
  - **性能：** 首次内容时间、每个场景期间的帧节奏和丢帧、输入到响应延迟、内存，以及该方案给应用增加的体积。
  - **无障碍：** 在每个平台的屏幕阅读器下，名称、角色、状态、焦点顺序和播报与核心契约的对等性。
  - **维护：** 一个 Astryx 发布版本和一个新 OS 版本在该平台上所需的工作，核心契约变更是否自动到达该平台，以及从 OS 发布到发布其新功能之一的时间。
  - **开发者速度：** 从编辑到在设备上看到的时间，以及应用代码跨平台复用的比例。
  - **依赖：** 每个必需的运行时依赖，按 FR13 分类。

  未通过 FR13 或低于 OQ1 阈值的候选不受支持，无论其其他分数如何。

- **FR13 — 必需依赖是平台、第一方或 React Native 自身的平台。** 原生平台的必需运行时依赖限于平台自身 SDK、由维护 Astryx 的组织维护的开源项目（例如 React、React Native、Hermes 和 StyleX
