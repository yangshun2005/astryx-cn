# 增量搜索结果系统规范

## 意图

用户在 typeahead 中输入时，立即看到与输入匹配的结果，这些结果来自页面已有的数据；服务器结果到达后，会加入同一查询的同一列表。每次按键最多改变列表一次；服务器结果只在已显示的行下方追加，因此指针或高亮下的内容不会移动，屏幕阅读器用户每个查询只听到一次结果计数，而不是每次结果到达都听到。

搜索源用一个或多个列表回答一个查询。每个列表都是该源在该时刻的完整答案；源自行负责本地与远程结果的合并、去重和排序。typeahead 显示当前查询的最新列表，并负责过期查询拒绝、高亮、加载反馈和播报。

## 非目标

- 源如何查找本地匹配、缓存先前查询、合并、去重或排序结果，以及后续列表的仅追加规则（FR2）。这些全部由源负责（DEC-1）。
- `bootstrap()`。它只返回一个列表。
- 源何时发送远程请求。先显示本地结果并希望延迟远程请求的源，自行延迟。
- 不传上下文调用 `search(query)` 的组件：`CommandPalette` 和 `ChatComposerInput` 触发菜单。它们显示已定列表（FR10）。`PowerSearch` 值编辑器渲染 Typeahead 和 Tokenizer，并通过它们获得此行为。
- 查询待定期间按 Escape。由 `component:BaseTypeahead` FR3 负责；部分列表遵循与已定列表相同的规则。
- 满足本契约的等效内部实现仍然有效。

## 需求

- **FR1 — 每个列表都是源的完整答案。** `search(query, context)` 接收一个可选的 `SearchContext`，其 `update(items)` 替换该查询显示的结果。源通过 `update` 或作为返回值给出的每个列表，都是该查询在该时刻完整、有序且无重复 `id` 的列表。typeahead 按原样显示每个非空列表，并受其结果上限限制；空的 `update` 保留已显示的行（FR5）。它从不合并、重排或去重列表。Tokenizer 按 `component:Tokenizer` FR13 的要求，从每个列表（部分或最终）中移除已提交的值。其创建行排在行之后，对于已搜索的查询，仅在查询定稿后出现，因此它不会提供一个待定服务器结果即将显示的值。
- **FR2 — 每次按键一次重排；后续列表仅追加。** 查询显示的第一个列表可以替换之前显示的行。同一查询的每个后续非空列表（包括最终列表）都保留已显示的行，按 `id` 保持在前，并保持 typeahead 显示它们的顺序，每个新行显示在其后。typeahead 先显示未分组行，然后按首次出现顺序显示每个分组，因此新行只能加入最后显示的分组，或在其后开始一个新分组。后续列表从不移除、重排或在已显示行上方显示新行，即使某个结果排名更高。`id` 相同但数据更新的行保持原位。当后续列表违反此规则时，typeahead 按原样显示，并在开发模式下警告源移动、移除或在已显示行上方插入了行。
- **FR3 — 返回值定稿查询。** 源返回的数组，或其 promise 解析的值，是该查询的最终列表。它按 FR2 替换任何较早的列表，结束查询的忙碌状态，并且是该查询最后显示的列表。查询定稿后的 `update` 调用无效。
- **FR4 — 只显示当前查询。** 不再当前的查询的列表会被丢弃，无论它来自 `update` 还是返回值。当用户输入更新的查询、选择结果、清空字段，或源被替换、typeahead 卸载时，查询不再当前。
- **FR5 — 待定查询显示其部分列表。** 查询待定期间，非空 `update` 显示其行并打开弹窗。空 `update` 保留已显示的行。控件保持忙碌并显示加载指示器，直到查询定稿。空结果行仅在查询以空最终列表定稿时出现。
- **FR6 — 高亮和滚动位置保持不动。** 新查询显示的第一个列表高亮其第一行。同一查询的后续列表到达时，高亮项保持高亮，列表保持滚动位置。后续列表从不将弹窗移到字段另一侧，也不在屏幕上移动已显示的行：字段上方的弹窗保持其高度，字段下方的弹窗仅在其下方空间内增长。超出部分通过滚动列表到达。当违反 FR2 的列表移动了高亮项时，高亮跟随该项；当它丢弃该项时，高亮第一行。Enter 选择高亮项。
- **FR7 — 项存在期间选项保持其身份。** 只要某项仍在一个查询的列表中，其选项元素和 id 保持不变。活动后代继续引用同一选项，因此辅助技术在行添加后不会重新读取高亮行。
- **FR8 — 每个查询一次结果播报。** typeahead 在查询定稿时每个查询播报一次结果计数。部分列表不播报任何内容。忙碌开始按 `spec:AST-086` FR6 和 FR8 的要求每个查询播报一次。
- **FR9 — 远程答案失败时保留已显示内容。** 当源的 promise 在当前查询有非空 `update` 后拒绝时，最后一个非空列表保留，查询定稿，并播报其计数。当它在当前查询没有非空 `update` 时拒绝，查询以空列表定稿并显示空结果行。弹窗关闭时 typeahead 自身 `cancel()` 后的拒绝不是失败答案：不播报任何内容，查询以当前查询的最后一个非空列表定稿；若没有，则不保留任何行，下次按键重新搜索。
- **FR10 — 单一答案仍是完整答案。** 从不调用 `update` 的源每个查询在查询定稿时显示一个列表。不传上下文的调用方调用 `search(query)` 并仅显示已定列表，FR1 使其完整。

### 平台支持

- 支持的功能/引擎下限：包支持的浏览器。本契约不使用 `search()` 已使用之外的任何平台功能。
- 不支持的行为：无。
- 浏览器证据：对行、高亮、活动后代、忙碌状态和播报通道在部分列表及其已定列表上的 DOM 和无障碍树检查。

## 当前状态影响

- `SearchSource.search` 增加一个可选第二参数，即带 `update(items)` 的上下文。`createStaticSource` 和所有现有源保持不变继续工作。
- `component:BaseTypeahead`：FR3 和 PR1 通过此处的 FR4 覆盖部分列表；AR4 通过此处的 FR8 每个查询播报一次；选项 id 在一个查询内跟随项身份（FR7）；开发警告报告违反 FR2 的后续列表。
- `component:Tokenizer`：FR13 适用于每个部分和最终列表；创建行等待已搜索查询定稿（FR1）。Typeahead 和 Tokenizer 通过 BaseTypeahead 继承此行为，不添加任何 Props。
- `family:input-fields`：忙碌反馈不变；待定查询在部分列表显示期间保持忙碌。
- 消费者文档：`SearchSource` 参考和 Typeahead 文档描述 `update`，以及先显示本地结果的源搭配 `debounceMs={0}` 并自行延迟远程请求。

## 决策日志

### DEC-1 — 搜索源自行合并结果

**参考：** `spec:AST-092/DEC-1`
**决策者：** cixzhang, 2026-10-22

"我认为合并服务器结果应该是搜索源的工作。"源知道哪些结果是本地的、哪些是远程的、如何去重，以及用户应以什么顺序看到它们，因此它给出的每个列表都是其完整答案。typeahead 仍是当前查询最新列表的渲染器。

已拒绝：typeahead 合并单独的本地答案和远程答案，这会使一条合并和排序规则成为每个 typeahead 的一部分。

### DEC-2 — 部分列表通过 `update` 到达；返回值保持最终

**参考：** `spec:AST-092/DEC-2`
**决策者：** cixzhang, 2026-10-22

`search()` 的返回值保持其含义，即最终列表，可选上下文添加部分列表。每个等待数组的调用方仍得到一个数组，源可以在返回前同步显示本地匹配，定稿即返回 promise 的结束。

已拒绝：`search()` 返回异步可迭代对象，这会破坏每个等待数组的调用方，且无法同步交付其第一个列表。

### DEC-3 — 服务器结果仅追加

**参考：** `spec:AST-092/DEC-3`
**决策者：** cixzhang, 2026-10-22

"服务器结果绝不应导致 typeahead 中已出现的项重排。""服务器结果返回时我们只应追加。每次按键只允许一次重排。"用户将指针或高亮对准他们能看到的行；行在他们对准后移动会使他们选错人。因此每次按键最多改变列表一次，该查询的每个后续列表都保持已显示行原位并在其下方添加（FR2）。

已拒绝：将排名更高的服务器结果放在已显示行上方，这会移动用户即将选择的行。
