# 主题本地令牌系统规范

<!-- review-applicability:v1 -->

```json
{
  "scope": "global",
  "triggers": {
    "tokens": ["DEC-1", "DEC-2", "DEC-3", "DEC-4", "DEC-5", "DEC-6"]
  }
}
```

## 意图

让受维护的主题在组件覆盖中复用自身的某个语义决策，而无需将该决策加入 Astryx 的可移植令牌词汇表。主题作者获得一条显式、可校验的路径，用于主题家族内的本地复用；组件作者和应用作者则保持现有的可移植令牌契约不变。

已发布的 API 是一个可选的 `DefineThemeInput.localTokens` 字段。提供该字段即显式让主题加入契约；省略该字段则保持现有行为。本地令牌以任意合法的 CSS 自定义属性名声明，并以完全相同的名称引用。前缀不授予、保留或限制所有权。后代继承加入状态，且只能通过已加入的精确 `extends` 谱系替换精确名称。仅发出 CSS 不产生契约，但由所属主题规范记录的已发布加入定义会产生契约：其精确名称和语义含义在该主题家族内是公开的，不跨主题可移植，也不面向 Core 组件源码。

本当前记录独立于任何特定主题是否已完成自身的采纳证据，管辖跨主题 API 和不变量。原始本地令牌接口已发布；2026-09-12 的命名修正已接受，尚待实现。主题本地名称、含义、值、映射和渲染证据仍由每个采纳主题的同位记录拥有。

## 非目标

- 改变现有 `DefineThemeInput.tokens` 路径的类型、接受输入、运行时或构建行为、宽松展开行为、名称、优先级、继承、输出或解析。
- 添加 `defineLocalTokens` 辅助函数、第二种创作操作、更短的角色标识符、引用别名或并行的本地令牌 API。
- 将主题本地名称加入 `TokenName`、`tokenVar`、`tokenVars`、`resolveThemeToken`、生成的可移植令牌文档或 Core 组件源码。
- 创建应用消费方令牌扩展机制。编译后的自定义属性是其受维护主题家族的实现输出，不授权应用代码依赖它。
- 定义任何采纳主题的角色含义、值、组件映射或证据。这些属于该主题的同位记录。

## 需求

以下需求是当前的跨主题契约。

- **FR1 — 本地令牌纯属增量、可选且显式加入。** `DefineThemeInput` 最多新增一个创作接口：可选的 `localTokens`。提供 `localTokens` 即显式让该主题加入新契约。后代只有通过扩展已加入的精确基主题才继承加入状态。既不提供该字段也不扩展已加入精确基主题的主题保持未加入状态，且必须产生字节等价的 `DefinedTheme` 数据、运行时行为、静态输出、包输出和解析行为。
- **FR2 — 现有令牌行为冻结，本地值复用其值契约。** 本契约不得改变 `tokens` 的类型、接受输入、运行时处理、静态处理、宽松未知键或宽泛展开行为、名称、优先级、继承、输出或解析。现有类型断言、展开、外部 CSS 变量和旧令牌引用不得收到新的警告、失败、重新解释或迁移要求。在可选的 `localTokens` 字段内，每个值必须接受完整的现有 `TokenValue` 契约：CSS 字符串或 `[light, dark]` 元组。运行时和静态构建必须应用现有 `tokens` 使用的相同值规范化语义，且不改变该现有路径，也不规范化主题名称。
- **FR3 — 一个精确名称贯穿每个阶段。** 本地令牌声明必须使用其完整的 CSS 自定义属性名作为 `localTokens` 键。同一精确字符串必须用于 `var(...)` 引用、`DefinedTheme` 数据、运行时 CSS、静态 CSS、继承替换以及生成的主题特定类型或元数据。任何转换都不得创建第二个标识符。
- **FR4 — 接受任意合法的自定义属性键。** 每个新声明的 `localTokens` 键必须是合法的 CSS 自定义属性名，且必须逐字节保留。不要求、保留、重写任何前缀，也不将其解释为所有者或加入元数据。主题名称和本地令牌键相互独立；本契约不定义首选的替换命名模式。
- **FR5 — 本地使用保持在受维护主题家族内。** 本地名称可由定义它的受维护已加入主题及其通过精确 `extends` 谱系加入的后代引用。它不得成为可移植的跨主题令牌或 Core 组件源码中的依赖。来自未加入旧路径的单纯 CSS 发出不产生契约。一旦已加入主题发布了在其同位主题级规范中记录的本地令牌，该精确名称和语义含义即成为该主题家族的公开兼容性契约。
- **FR6 — 扩展是精确名称、加入状态和谱系感知的。** 后代仅从已加入的精确 `extends` 基主题继承加入状态和声明。它只能通过重述继承的完整名称来替换继承的本地令牌。新声明的名称由声明主题拥有，无论其拼写如何。前缀、后缀或值相似性不得创建所有权或谱系，子主题不得声称另一主题的声明。
- **FR7 — 校验仅对已加入主题原子化。** 运行时和静态构建必须共享一个递归校验器。对于直接加入或通过已加入精确基主题加入的主题，它必须在产生部分输出之前校验每个声明的自定义属性语法、精确所有者和谱系、与可移植 `tokens` 的冲突，以及本地令牌值、组件覆盖、媒体表面和适配中精确声明引用之间的循环。适配 `value.tokens` 键若与有效本地声明精确匹配，必须失败，以便写入使用 `value.localTokens` 并保留所有者、谱系和循环校验。`var()` 引用仅当与有效已加入声明精确匹配时才是本地边；所有其他自定义属性引用保持外部。前缀无校验含义。
- **FR8 — 未加入的旧行为原样保留。** 当 `localTokens` 缺失且精确基主题未加入时，运行时和静态构建不得为 CSS 自定义属性引用添加新的扫描、拒绝、警告、保留或解释。现有自定义属性保持不变。维护者可将该行为保持未加入，或通过提供 `localTokens` 显式迁移；前缀不改变任一途径。
- **FR9 — 源码主题和构建主题保留同一加入谱系。** 源码定义和构建的主题必须保留等价的精确本地令牌映射、加入状态和谱系元数据，使后代无需基础样式表即可接受、继承、替换、拒绝和发出相同名称。
- **FR10 — 已发布的名称和含义是兼容性义务。** 一旦已加入的本地令牌发布，其精确名称和记录的语义含义即成为所属主题家族的公开契约。重命名本地令牌或其已加入主题，或改变该含义，必须使用显式审查的迁移或别名，在其兼容窗口内保留先前的精确名称、含义和谱系契约。禁止静默替换键、语义扩大、所有者重新分配和推断后代迁移。
- **FR11 — 同位主题规范拥有定义和映射。** 每个主题本地令牌定义必须位于所属主题的同位主题级规范中，包括其精确名称、语义含义、值、映射、兼容性和渲染证据。当长生成名称准确命名其应用的所有上下文共享的含义时，该名称可接受。添加映射是主题规范兼容性审查：上下文必须真正匹配记录的含义，并必须为其实际浅色/深色和相关交互状态提供渲染证据。

### 创作形态

`defineTheme` 仍是唯一的创作操作。每个 `localTokens` 键是用于 `var(...)`、`DefinedTheme`、继承和发出输出的完整 CSS 自定义属性名。键逐字节保留，无必需前缀。值复用现有 `TokenValue` 契约，并完全按现有 `tokens` 值的方式规范化。采纳的 `theme:*` 记录拥有每个具体角色、值和组件映射。

### 平台支持

- 支持的功能/引擎下限：与现有 Web 主题相同的 CSS 自定义属性、`light-dark()`、主题作用域和浏览器支持。
- 不支持的行为：无法保留本地角色及其谱系的平台编译器必须明确拒绝该已加入输入，而不是静默省略它或将 CSS 拼写暴露为共享跨平台 API。
- 浏览器证据：每个采纳主题在真实 Chromium 中验证其实际组件映射和颜色模式。名称、校验、继承以及运行时/静态一致性是结构性的，无需视觉证据即可测试。

## 当前状态影响

当前 `main` 保持其封闭的可移植核心/领域令牌词汇表，并发布了一等 `localTokens` 字段及原始基于前缀的键校验。2026-09-12 修正仅放宽接受的本地令牌键拼写；实现仍待完成。到达宽松旧路径的未知键仍可序列化，但只有显式 `localTokens` 加入才创建所有权、引用闭包和谱系校验。

- `architecture:theme-authoring-contract` 拥有可选 `localTokens` 输入、其精确名称映射、显式加入状态、扁平化继承和谱系元数据；
- `architecture:theme-compilation` 通过共享运行时/静态编译器发出该精确映射，并仅对直接加入或通过已加入精确基主题加入的主题应用一个递归校验器；以及
- `architecture:theme-tokens` 继续拥有未改变的可移植词汇表，并明确将主题本地名称排除在其公共辅助函数和文档之外。

这些当前架构记录投射已批准的行为并引用适用的 AST-006 决策。前缀无关的键接受仍是已命名的符合性差距，直到其实现落地。草稿主题记录可引用本当前规范，同时保持其自身的值、映射和证据决策未解决。

### 兼容性与采纳

- 采纳按受维护主题家族进行且可选。现有主题不会仅因字段存在而迁移。
- 省略 `localTokens` 且不扩展已加入精确基主题的主题在 `DefinedTheme`、运行时、静态和包输出中保持字节等价。其 CSS 自定义属性引用不收到新的扫描、拒绝、警告、保留或解释。
- 加入接受任意合法自定义属性键。要迁移现有自定义属性，维护者需在 `localTokens` 中显式声明该精确键；前缀不影响资格或所有权。
- 现有 `tokens` 和外部变量行为保持字节等价，包括宽松宽泛展开和运行时输入。
- 本地名称和记录的含义在发布后成为公开主题家族兼容性义务；它们永远不会成为可移植跨主题或全局 Core 令牌承诺。来自未加入旧路径的单纯自定义属性发出不创建该契约。
- 每个本地定义和映射位于所属包的同位主题规范中。每个新映射审查其上下文是否真正匹配记录的含义，并在采纳前提供渲染证据。
- 后代兼容性遵循显式加入和精确谱系。已发布的已加入主题或令牌重命名，或语义含义改变，需要显式迁移或别名，后代才能移动。
- 基础设施实现携带自己的 Changeset。后续采纳主题输出变更携带单独的发布说明。

### 完成标准

AST-006 保持 `shipped`；2026-09-12 命名修正在其实现满足以下标准并与已发布契约一致时达到符合性：

- 可选 `DefineThemeInput.localTokens` 是唯一的新本地令牌创作接口，其存在是根加入触发器；
- 无 `localTokens` 且无已加入精确基主题的主题被证明字节等价，无新的自定义属性扫描、拒绝或警告；
- 本地值接受两种现有 `TokenValue` 形式——CSS 字符串和 `[light, dark]` 元组——且运行时/静态规范化匹配现有 `tokens` 值路径而不改变它；
- 每个合法 CSS 自定义属性键在声明、`var(...)` 使用、`DefinedTheme`、源码/构建继承和发出输出中被接受并逐字节保留，无前缀语义；
- 后代仅从已加入精确基主题继承加入状态；拼写永不创建所有权或谱系；
- 自定义属性语法、令牌冲突、精确所有者和谱系以及循环失败仅对已加入主题原子化且在运行时和静态路径间相等；
- 构建主题保留加入和精确谱系元数据，足以让后代无需基础样式表；
- 每个已发布本地定义由其同位主题级规范拥有，其精确名称和语义含义被视为该主题家族内的公开兼容性契约；
- 每个添加的映射通过主题规范兼容性审查，并提供渲染的浅色/深色和相关交互状态证据，表明其上下文真正匹配记录的含义；
- 公共可移植令牌类型、辅助函数、文档和 Core 组件源码不将本地名称暴露为跨主题 API；以及
- 每个采纳者的同位 `theme:*` 记录拥有其名称、含义、值、映射、迁移和渲染证据。

## 决策日志

以下决策由 `cixzhang` 作为本当前规范的一部分批准。

### 修正 — 使本地令牌名称前缀无关

**决策者：** `cixzhang`，`2026-09-12`

`localTokens` 接受任意合法 CSS 自定义属性键。前缀对有效性、所有权、加入或谱系无影响。这取代先前记录在 FR4、FR6–FR8、DEC-2、DEC-3 和 DEC-4 中的命名模式和保留前缀条款。精确键保留、显式加入、所有者元数据、精确 `extends` 谱系、继承、可移植令牌冲突检查和循环检查仍然有效。本修正不定义替换命名模式。

### DEC-1 — 添加一个可选本地令牌字段而不改变 tokens

**引用：** `spec:AST-006/DEC-1`
**决策者：** `cixzhang`，`2026-08-31`

使用纯增量的可选 `DefineThemeInput.localTokens` 字段。提供它即显式让主题加入；精确后代可从已加入基主题继承该加入状态。保持 `defineTheme` 为唯一创作操作，并保留每个现有 `tokens` 类型、输入、运行时、构建、展开、优先级、继承、输出和解析行为。无 `localTokens` 且无已加入精确基主题的主题保持字节等价，无论自定义属性拼写如何。

拒绝：`defineLocalTokens` 辅助函数、并行 API、从键拼写隐式加入、可移植令牌词汇表的模块增强，或对现有令牌路径的更严格校验。

### DEC-2 — 保留一个精确、前缀无关的名称

**引用：** `spec:AST-006/DEC-2`
**决策者：** `cixzhang`，`2026-08-31`；修正于 `2026-09-12`

`localTokens` 声明接受任意合法 CSS 自定义属性键。声明键即 CSS 变量，引用使用同一逐字节名称。不要求、保留、重写或解释任何前缀，主题名称不决定键。本决策不定义首选的替换命名模式。

拒绝：生成名称、引用别名、隐藏规范化，以及任何基于前缀改变有效性或所有权的命名规则。

### DEC-3 — 将替换绑定到精确扩展谱系

**引用：** `spec:AST-006/DEC-3`
