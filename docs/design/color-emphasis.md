# 颜色强调设计规范

## 用户意图

用户应能快速找到主要操作，并理解表面与状态角色，而无需解读任意颜色。颜色应在所有支持的模式和主题下保持可读性与层级。

## 设计原则

- **DR1 — 前景与背景是同一个决策。** 颜色选择必须在所处表面的上下文中评估。
- **DR2 — 中性色遵循语义角色。** 交互叠加层、轨道、内容容器和独立元素即使中性值相近，也必须保持可区分。
- **DR3 — 强调保持稀缺。** 局部操作组应只暴露一个明确的主要强调，而非让每个操作平等竞争。
- **DR4 — 状态遵循其规范反馈契约。** 颜色强调必须保留 `design:system-states` 定义的非颜色线索和突出程度，不得另创状态处理方式。
- **DR5 — 交互叠加层保留上下文。** 悬停和按下处理应在视觉上与底层表面结合，而非用无关的不透明块替换它。

## 结构与层级

| 角色       | 用途                       | 必需关系                             |
| ---------- | -------------------------- | ------------------------------------ |
| 基础表面   | 建立页面、容器或元素上下文 | 决定前景选择的含义与可读性           |
| 前景       | 承载文本、图标或边界信息   | 在配对的表面上保持可读               |
| 交互着色   | 传达瞬时响应               | 保留底层表面的身份                   |
| 主要强调色 | 将注意力引向最重要的局部操作 | 在视觉上强于同级操作                 |

## 状态表示

静止、悬停、按下、聚焦、选中和禁用状态必须在每种支持的模式下保持感知上的区分。状态表示由 `design:system-states` 负责。辅助文本和禁用文本不得仅因两者都比正文更安静而变得无法区分。

## 响应式与输入行为

- **DR6 — 强调在密度变化下存续。** 当操作折叠或移动时，主要操作必须保持可识别，且不放大其余每个控件。
- **DR7 — 悬停颜色是可选反馈。** 触摸和键盘路径必须在不依赖悬停着色的情况下保留状态含义。

## 无障碍意图

前景/背景配对必须在所有支持的模式下保持可读。颜色强调不得削弱 `design:system-states` 负责的非颜色状态线索。确切阈值和机械对比度验证仍属于无障碍与审计职责。

## 代表性示例

- 工具栏暴露一个主要操作，次要和破坏性操作保持清晰，但不共享相同的强调。
