# 图标设计规范

## 用户意图

图标是简单的图形界面元素，用于表示常见操作、概念和状态。图标应帮助用户理解界面、完成任务、找到路径，同时不增加视觉噪音，也不迫使用户去解读不一致的符号。

## 设计原则

- **DR1 — 清晰。** 图标必须使用简单、可识别的形式，传达其预期含义并帮助理解。
- **DR2 — 有意图。** 每个图标在其局部上下文中必须有明确作用。设计者在添加另一个图标前应评估整个容器和页面，避免装饰增加认知负担。
- **DR3 — 一致。** 重复出现的概念、操作、几何形状、尺寸角色和图形风格应在产品内保持一致。组件应复用系统语义图标，不应为已有含义引入定制符号。
- **DR4 — 尺寸跟随语义角色。** 字形尺寸必须由其功能决定，不能仅依据最近的可用空间或图形本身的固有比例。
- **DR5 — 默认使用描边图形。** 当图标族为同一符号提供描边和填充版本时，组件应默认使用描边版本，除非符合允许的填充使用条件。
- **DR6 — 颜色辅助含义。** 图标颜色必须遵循已批准的前景色、语义色或受限的非语义色角色。颜色本身不得单独传达概念或状态。
- **DR7 — 字形与目标分离。** 图标图形不得替代交互容器、可操作点击目标、焦点处理或无障碍名称。

## 结构与层级

### 含义角色

| 角色         | 用途                             | 必需关系                                                                     |
| ------------ | -------------------------------- | ---------------------------------------------------------------------------- |
| 信息性图标   | 在相邻标签之外添加信息或含义     | 仅在具备无障碍名称且有足够解释时可独立使用                                   |
| 装饰性图标   | 强化附近文本，不添加独立含义     | 必须伴随已传达含义的内容；通常使用描边图形                                   |
| 交互性图标   | 表示交互控件内的操作             | 所属 Button、IconButton、链接或其他控件负责交互、状态、焦点、名称和目标      |
| 语义图标     | 强化信息、成功、警告或错误含义   | 匹配的语义图标与颜色配合使用；含义不依赖颜色即可获得                         |
| 对象或标志图标 | 标识特定对象、产品或品牌       | 仅在该对象的识别具有相关性时使用；不作为类别或分区的通用装饰                 |

### 尺寸角色

Astryx 提供四种 Icon 尺寸。数值为 16px 根字号下的 px 等价值；Icon 继续随文档根字号缩放。

| 角色         | 当前 Icon 尺寸 | 用途与当前关系                                                     |
| ------------ | -------------- | ------------------------------------------------------------------ |
| 紧凑指示器   | 12px（`xsm`）  | 辅助指示器、元数据和密集的可操作元素                               |
| 标准控件     | 16px（`sm`）   | 大多数控件和展开/收起元素；当前 Button `sm` 和 `md` 的图标框       |
| 突出控件     | 20px（`md`）   | 大型控件和视觉上重要的纯图标操作；当前 Button `lg` 框              |
| 展示或对象   | 24px（`lg`）   | 大型独立符号、对象标识或特殊展示级处理                             |

这些角色描述视觉意图，不是新的公开 Icon 尺寸名称。组件契约负责其角色分配。裸 Icon 当前默认为 `md`（20px），而许多组合控件明确将其图标槽限制为 16px 或 20px。一项进行中的上下文尺寸调整可能使省略的 Icon 尺寸继承自其所属控件；本记录不依赖该实现落地。

### 描边与填充图形

描边图形是起点。当满足以下一个或多个条件时，可使用填充图形：

1. 图标同时传达激活或开启状态，例如开关或选中的导航项。
2. 图标为 12px 等价值或更小，且填充能明显改善识别。
3. 信息性图标带有持久语义色，例如信息、成功、警告或错误状态。
4. 图标有意需要更高强调，例如主要操作或对象标识。
5. 图标出现在媒体或其他视觉繁忙背景上，填充能改善对比度或识别。
6. 图标是标志或品牌标记，其规范图形为填充。

符号的形状或次要前景色本身不足以要求填充。Astryx 当前的默认 chevron、关闭标记、搜索图标和排序箭头在所有尺寸下均为描边，而状态图标为填充，more 和 stop 等本质实心标记保持实心。同类控件应使用统一的图形语言，但统一性不覆盖其语义角色。

填充例外必须有意图且局部化。它不使填充图形成为全局默认。没有有意义描边对应物的本质实心基元，不因包含实心形状而被视为填充变体。

## 状态表示

| 状态或上下文     | 必需表示                                                         | 允许的变化                                               |
| ---------------- | ---------------------------------------------------------------- | -------------------------------------------------------- |
| 静止             | 使用角色的正常尺寸、颜色和描边图形，除非适用填充例外             | 主题图形和光学调整可变化                                 |
| 激活或开启       | 可从描边变为填充，同时保留一个可识别符号                         | 另一种已确立的非填充状态处理可强化状态                   |
| 紧凑指示器       | 保持从属且可识别；12px 或更小时填充有助于识别则允许              | 尺寸特定图形可改善可读性                                 |
| 语义状态         | 状态图标与匹配的语义色及无障碍含义配对                           | 填充图形可提供持久强调                                   |
| 禁用             | 使用已批准的禁用前景色，不丢失识别性                             | 图形与角色保持一致                                       |
| 媒体或繁忙表面   | 在可变内容上保持对比度和识别性                                   | 可使用填充图形和继承的高对比前景色                       |
| 替代主题         | 含义、角色层级和描边/填充意图保持可识别                          | 图标库和具体图形可不同；角色特定尺寸需要暴露目标         |

描边到填充的变化不得作为状态区分的唯一线索，该区分必须保持可感知。程序化状态、无障碍命名、位置、颜色或其他已确立的处理必须继续承载该状态。

## 颜色角色

Astryx Icon 当前提供 `primary`、`secondary`、`tertiary`、`disabled`、`accent`、`success`、`warning`、`error` 和 `inherit`，以及命名调色板颜色。设计意图为：

- **Primary** 承载普通高强调图标内容。
- **Secondary 和 tertiary** 承载辅助图标内容。其当前 token 映射可能重合，但语义角色保持区分。
- **Disabled** 传达不可用的图标内容，不暗示状态。
- **Accent** 在所属组件赋予该含义时，传达选中强调或信息。
- **Success、warning 和 error** 保留用于匹配的语义结果。
- **Inherit** 让所属控件或表面提供正确的前景色，包括媒体和其他繁忙表面。
- **命名调色板颜色** 不从 Icon 获得语义含义。仅在所属组件或产品定义并一致应用非语义类别映射时使用。

`placeholder` 和 `onMedia` 不是当前 Icon 颜色值。组件可通过继承或限定主题目标创建这些视觉角色，但本设计记录不发明新的 Icon API 值。

## 响应式与输入行为

- **DR8 — 密度不抹除含义。** 密集布局可为辅助指示器选择紧凑角色，但主要控件必须保持可识别为控件。
- **DR9 — 输入适配属于目标。** 触摸或粗指针模式可增大包含目标或间距，语义角色不变时无需改变字形。
- **DR10 — 角色变化必须显式。** 响应式组合不得仅为适配而静默地在紧凑、标准控件、突出控件和展示角色之间移动图标；组件或族契约必须确立该变化。
- **DR11 — 紧凑图形保持识别性。** 在 12px 等价值或更小时，当描边资源失去清晰度，主题可选择填充或光学简化图形。16px 图标不因尺寸小就变为填充；仍须适用填充使用条件之一。符号含义和周围布局必须保持不变。

## 组合指导

### 控件中的图标

- 交互性图标必须置于 IconButton、Button、链接或其他提供交互状态、焦点、无障碍名称和足够目标的控件中。
- 裸 Icon 不得通过附加点击处理器而变为交互性，除非有所属控件。

### 标签页中的图标

- 前置标签页图标可标识目标或强化可见标签。装饰性图标在增加干扰或宽度而无有用识别时应省略。
- 选中图标可变化以强化选中状态，前提是标签和标签页语义继续承载该状态。
- 状态图标、徽章和状态点应放在标签页的尾部内容或状态位置，而非替换标签页标签。

### Token 和徽章中的图标

- 信息性状态处理将语义图标和颜色配对，使组合传达状态，而非任意重新着色容器。
- Token 或徽章可通过组件拥有的语义变体协调其表面和图标；仅嵌套图标不重新定义容器含义。

### 链接中的图标

- 链接应主要使用文本。图标可在添加有用视觉提示时补充文本。
- 当目标在上下文中可识别且 Link 获得非空无障碍 `label` 时，可使用纯图标链接。当交互应表现为控件而非内联导航时，优先使用带 `href` 的 Button。

### 列表中的图标

- 不可选择的描述列表和菜单列表通常应使用标准 16px 等价值尺寸的描边图标和支持的前景色角色。
- 当本记录中另一规则适用时，可使用填充图形、紧凑尺寸或命名调色板颜色；仅装饰不足以作为增加强调的理由。

### 标题中的图标

- 当标题标识特定对象且图标实质性帮助识别时，标题可包含对象媒体。
- 大多数类别和分区标题不应包含图标；通用媒体增加噪音而不澄清分区。

### 导航中的图标

- 导航图标必须有意图地选择：使用清晰、简单的符号表示目标，而非通用装饰标记。
- 选中导航可使用组件拥有的描边到填充配对，前提是文本、`aria-current` 或其他已确立处理继续标识选中。

## 无障碍意图

- 当信息尚未以文本提供时，信息性图标需要无障碍图像名称。当符号单独可能含糊时，应提供解释性文本或工具提示。
- 装饰性图标不暴露重复名称，并与传达含义的可见文本保持配对。
- 图标图形必须在其渲染尺寸下保持可识别。Astryx 不要求 16px 或以下的所有图标填充：当前默认大多为描边，状态图标为填充，本质实心标记保持实心。优先使用尺寸特定或光学调整图形；仅当上述填充使用条件适用时使用填充。
- 图标前景色必须与其背景保持适用对比度。
- 交互性图标需要足够的周围空间用于识别，以及由其控件拥有的可操作目标。

## 代表性示例

- 分组行展开 chevron 是整个分区的交互控件，因此其预期标准角色为 16px 等价值，而非 12px 辅助指示器。Astryx 当前默认 chevron 保持描边。
- 表格排序方向箭头是与列标题关联的紧凑指示器，因此使用 12px 等价值角色，而按钮和 `aria-sort` 承载交互和状态。它不需要填充图形。
- 持久语义信息提示可使用填充图形和 accent 颜色，前提是附近内容或无障碍名称加以解释。
- 开/关控件可将关闭状态配描边图形、开启状态配对应填充图形，同时其语义状态独立可用。
- 大型纯图标 Button 在包含目标和间距支持时使用 20px 等价值突出控件字形；纯图标不自动意味着突出。
- 24px 等价值图标保留用于展示级或对象处理，而非默认图标按钮字形。
- 不可选择的列表项通常使用标准尺寸描边图标，配 primary 或 secondary 前景色。

## 组件契约链接

- `component:Icon` 拥有共享的 12/16/20/24 尺寸词汇、裸 Icon 的 `md` 默认、缩放行为、目标、颜色 API 和渲染语义；本记录将设计意图分配给角色、颜色和图形选择。
- 交互组件拥有其目标、状态、焦点、无障碍名称和图标槽几何；Icon 仍是该所有者内部的字形。
- `component:Table` 拥有哪些生成的 Table 可操作元素是紧凑指示器或标准控件。分组行展开是本记录生效后显式标准控件链接的首个候选。
- `architecture:icon-resolution-and-component-slots` 拥有语义名称和图形解析。组件在注册表提供图形前选择位置、尺寸、颜色和状态；注册表不是这些角色的所有者。
- `architecture:component-theming-surface` 拥有主题化保证。共享 Icon 目标反映 `size` 和 `color`，因此主题可一致地样式化现有值。局部组件角色覆盖仍需要具备相关属性保证的限定所属目标；本记录不创建该目标。

## 决策日志

### DEC-1 — 默认使用描边图形，并有意的填充例外

**引用：** `design:iconography/DEC-1`
**决策者：** 待设计负责人批准

当存在有意义的配对时，从描边图形开始。仅对激活状态、经验证的 12px 或更小紧凑识别、持久语义状态、有意强调、繁忙背景或规范标志使用填充对应物。保持同类控件间的一致性，但不将符号形状或次要颜色视为自动允许填充。

已拒绝：将填充图形作为通用默认、填充 16px 或以下的所有图标、按类别填充 chevron 和关闭标记、将填充作为唯一状态线索，或仅因资源存在而选择填充。

### DEC-2 — Astryx 使用 12 / 16 / 20 / 24 角色阶梯

**引用：** `design:iconography/DEC-2`
**决策者：** 待设计负责人批准

12px 等价值用于紧凑辅助指示器，16px 等价值用于标准控件和展开/收起，20px 等价值用于突出控件如大型图标按钮，24px 等价值用于展示级或对象处理。裸 Icon 当前默认为 20px 等价值 `md`；组合组件可独立限制其图标槽。

已拒绝：原样导入旧的三尺寸 12/16/24 配置、将 16px 称为基元 Icon 默认、对所有图标使用单一尺寸，或不顾含义从可用空间选择尺寸。

### DEC-3 — 信息性和装饰性图标有不同内容义务

**引用：** `design:iconography/DEC-3`
**决策者：** 待设计负责人批准

信息性图标可承载标签之外的含义，因此独立使用时需要无障碍名称和足够解释。装饰性图标不添加独立含义，与文本保持配对，并对辅助技术隐藏以避免重复播报。

已拒绝：将每个图标视为信息性，或允许装饰性图标无标签独立存在。

### DEC-4 — 主题在其所属表面调整共享和组件角色

**引用：** `design:iconography/DEC-4`
**决策者：** 待设计负责人批准

主题可为共享语义图标名称替换图形，并可通过共享 Icon 目标一致地调整现有 `Icon.size` 值。局部角色（如某组件的展开/收起控件）应改用组件拥有的限定目标，前提是该目标存在并保证相关属性。组件继续拥有位置、状态和无障碍语义；本记录不创建新目标或保证。

已拒绝：添加临时尺寸名称、仅为影响一个组件而更改共享尺寸、将图形注册表作为组件行为或状态的所有者，或假设当前每个含图标角色都可独立主题化。

## 内容边界

本文件定义图标的公开视觉、组合和无障碍意图。它不规定特定图标库、资源管理工作流、请求流程、实现框架、prop 语法、目标选择器、注册表描述符或迁移工具。它不改变 Icon 已发布的尺寸词汇或默认值，不定义点击目标阈值，不选择单个 SVG 几何，也不实现主题覆盖。
