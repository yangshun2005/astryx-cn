# 动效设计规范

## 用户意图

动效应说明发生了什么变化、内容来自何处，同时不让界面显得浮夸或迟钝。即使减少动效，每次状态变化仍应可理解。

## 设计原则

- **DR1 — 动效承载含义。** 动画必须解释响应、连续性、进入、退出或空间变化，而非装饰静态内容。
- **DR2 — 权重决定时长。** 小型局部反馈应比大型进入、退出或持续运动更快。
- **DR3 — 运动自然收敛。** 缓动应传达受控的减速，而非装饰性的弹跳或弹性；主题的表现性特征只可在进入和移动时过冲（`spec:AST-108`）。
- **DR4 — 稳定内容保持稳定。** 动效应避免不必要的布局扰动，并保持阅读和交互上下文。
- **DR5 — 减少动效保留含义。** 每个动画过渡必须有即时或最小移动的形式，传达相同的状态变化。`design:reduced-motion` 负责当前的减少动效规则。

## 结构与层级

| 角色         | 用途                     | 必需关系                             |
| ------------ | ------------------------ | ------------------------------------ |
| 起始状态     | 确立正在变化的内容       | 在连续性清晰前保持可识别             |
| 过渡提示     | 连接起点与终点           | 仅使用解释变化所需的运动             |
| 目标状态     | 展示完成的结果           | 收敛后无残留装饰性活动               |
| 减少动效路径 | 不经过位移传达相同结果   | 在需要处保留时序和状态含义           |

## 状态表示

悬停和按下使用最轻量的有效响应；进入和退出可使用更明显的过渡；大型或持续运动需要更强的用户理由。加载和状态必须在无动画时仍可理解。

## 响应式与输入行为

源 wiki 除上述原则外，未确立响应式路径、中断或特定输入的动效规则。除下述悬停显示规则外，这些问题留待有独立证据的决策。

### 悬停显示延迟

悬停显示交互指任何由支持悬停的指针触发显示、展示或展开的内容：工具提示、悬停卡片、悬停打开的菜单或浮出层、悬停时展示内容的容器、预览，或悬停打开的弹出层。

- **进入延迟。** 悬停显示交互必须在渲染或更新前等待一小段延迟，以免指针掠过触发器时触发急切的渲染或更新。界面所有者选择默认延迟；其记录可将延迟设为零，并附理由（`architecture:interaction-modality` INV11）。
- **退出保护。** 离开触发器不得使内容闪烁消失：内容保持到短暂的退出延迟结束，或对容器展示而言，直到其淡出完成，使掠出再掠入读作一次悬停。在 `prefers-reduced-motion: reduce` 下，容器展示的淡出为即时（`design:reduced-motion` DR3），因此其内容立即离开。
- **特定于指针。** 键盘焦点立即显示，无停留。悬停门控从不延迟触摸或粗指针；点击是否打开界面由所有者决定（`architecture:interaction-modality` INV4）。
- **组内交接。** 在一组触发器内，指针从一个已打开的触发器移到下一个时，立即显示下一个；进入延迟仅适用于首次打开（`architecture:interaction-modality` INV11）。
- **默认开启；可调整。** 延迟和保护默认开启，各所有者设定自己的默认值。定时器驱动的界面（工具提示、悬停卡片、悬停打开的菜单或浮出层）将其暴露为 `delay` 和 `hideDelay`（毫秒），调用方仅在明确用例下缩短或移除。容器展示的时序保留在 CSS 中；调用方通过 `hoverDelay` 选择启用其进入延迟，其退出淡出无选项。

## 无障碍意图

不得要求通过动效感知状态、层级或完成。减少动效应抑制不必要的位移，同时保留反馈。动画内容不应反复从阅读或输入中抢夺注意力。

## 代表性示例

- 按下的控件立即响应，不启动装饰性运动。
- 界面进入说明新内容归属何处，然后安静收敛。
- 减少动效模式展示相同的完成状态，无空间位移。

## 决策日志

本记录从公开 Design Conventions wiki 提炼动效意图，不复制时长值、CSS 属性或审计机制。一点已决定：

### DEC-1 — 每个悬停显示交互都做防抖

**引用：** `design:motion/DEC-1`
**决策者：** `cixzhang`，`2026-10-11`；`delay` 和 `hideDelay` 选项，`2026-11-06`

每个悬停显示交互都需要一小段延迟，防止掠过时急切的渲染和更新，并需要退出保护，使内容不闪烁消失。延迟的存在是为了防止用户掠过界面时在移动指针过程中导致卡顿的重渲染；这是输入处理，不是动效品味。键盘焦点立即显示，粗指针不受门控。默认开启；调用方仅在明确用例下退出。定时器驱动的悬停界面（工具提示、悬停卡片、悬停打开的菜单和浮出层）将等待暴露为 `delay`，退出保护暴露为 `hideDelay`（毫秒），如 Tooltip、HoverCard 和 TopNavMenu 已做的那样。在一组触发器内，指针从一个已打开触发器移到下一个时立即显示下一个（`architecture:interaction-modality` INV11）。在此决策内拒绝移除界面的默认延迟：它以指针保护换取对键盘或触摸用户无益，后者已立即看到内容。
