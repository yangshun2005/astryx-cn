## 用户意图

重排列表或行集合的人应能理解什么在移动、将落到哪里、何时提交变更。指针和键盘路径应传达相同的候选位置，且不让周围条目提前跳动。

本方案用于在集合内改变顺序。自由画布放置和文件拖放目标需要单独的设计规范。

## 设计原则

- **DR1 — 重排从显式手柄开始。** 交互必须从专用可操作元素启动，使激活是有意的，且其他条目操作仍可用。
- **DR2 — 移动中的条目保持可识别，但不显得被抬起。** 源条目和跟随指针的预览必须读作同一处于临时移动状态的条目，且不得暗示卡片被抬起。
- **DR3 — 集合变更前预览放置位置。** 清晰的插入提示必须标记候选位置，周围条目在提交前保持稳定。
- **DR4 — 提交只发生一次。** 集合必须在放下或释放时采用新顺序，而不是在指针越过条目时反复提交。
- **DR5 — 完成后恢复正常层级。** 临时拖拽样式必须在放下或取消时立即消失，已落定的条目必须恢复正常对比度和深度。

## 结构与层级

| 角色         | 用途                     | 必需关系                                         |
| ------------ | ------------------------ | ------------------------------------------------ |
| 重排手柄     | 启动并保持交互所有权     | 属于单个条目，且与条目激活保持可区分             |
| 静止源条目   | 拖拽期间保留条目原始位置 | 提交前保持原位，并与预览共享临时样式             |
| 移动预览     | 跟随指针移动             | 复制源条目身份，但不增加抬起卡片的高度           |
| 插入提示     | 标记候选有序位置         | 出现在集合排序轴上的条目之间                     |
| 周围条目     | 提供稳定的空间上下文     | 重排提交前不移动                                 |
| 落定集合     | 显示结果顺序             | 完成后每个条目恢复正常状态                       |

## 状态表示

| 状态     | 必需表示                                             | 允许变化                                     |
| -------- | ---------------------------------------------------- | -------------------------------------------- |
| 静止     | 手柄可被发现，但不压过条目内容                       | 手柄位置可随集合族变化                       |
| 拖拽中   | 源条目和移动预览使用相同的临时降低强调样式           | 指针预览可在两个轴上自由移动                 |
| 候选位置 | 清晰的强调插入线标记条目将落到的位置                 | 线长和缩进可随行几何变化                     |
| 已放下   | 条目落定到已提交顺序，临时拖拽样式清除               | 落定动效可使用系统的快速移动语言             |
| 已取消   | 原始顺序和正常对比度立即恢复                         | 即使启用了正常动效，取消也可立即生效         |

## 响应式与输入行为

- **DR6 — 放置跟随集合轴。** 指针预览可自由移动，但候选顺序必须在集合的排序轴上计算。
- **DR7 — 键盘和指针共享插入提示。** 键盘重排必须暴露与指针重排相同的候选位置表示。
- **DR8 — 减少动效时直接更新。** 当动效被减少时，最终顺序必须直接更新，不带动画移动。

## 无障碍意图

整个操作期间焦点应保持在重排手柄上。位置变化、取消和完成应以无需看到预览即可理解的方式播报。临时降低强调样式仅在主动重排期间可接受，且不得降低内容的持续可读性。

焦点机制、键盘命令、实时区域措辞和集合变更属于组件和族契约。

## 代表性示例

- 一行从其手柄开始移动；原始行和指针预览暂时变淡，同时一条线标记候选间隙。
- 键盘移动每次改变同一插入提示一个位置，焦点保持在手柄上。
- 放下时提交一次，然后集合落定到新顺序。

## 组件契约链接

`spec:AST-103` 将此方案应用于每个可重排集合，包括其键盘重排模式（DR7）。

实现差距：Lab 的 ListInput 和 TransferList 在键盘重排时不绘制插入线（DR7）；ListInput 的键盘抓取模式在提交前移动行（DR3）；两者都自行构建拖拽预览（`architecture:component-style-authoring` INV7）。

## 决策日志

### DEC-1 — 重排遵循本设计，而非滑开让位

**参考：** `design:ordered-collection-reordering/DEC-1`
**决策者：** `cixzhang`，`2026-10-26`

拖拽条目时，周围条目保持原位，源条目留在原地并变暗，移动预览跟随指针，条目间的强调插入线标记将落到的位置；条目在放下时重排一次，取消则立即恢复。键盘重排显示相同的插入线。对于小放置目标，放下标记（仅在释放时带动效）比在指针下移动的相邻条目更准确。

已拒绝：拖拽期间相邻条目滑开让位。
