# 层级高度设计规范

## 用户意图

用户应能分辨哪个表面位于另一个表面之上，而不会注意到一套过度构建的阴影系统。看起来更高的表面也应覆盖较低的内容，且不被裁剪。

## 设计原则

- **DR1 — 感知顺序与实际顺序一致。** 看起来更高的表面，其行为必须表现为更高的层。
- **DR2 — 深度保持克制。** 阴影和边缘应传达分隔感，而不应成为主导的视觉特征。
- **DR3 — 以一种边缘语言为主。** 表面应使用定义的边缘或柔和的高度作为其主要边界，而不是以全强度同时使用两者。
- **DR4 — 状态环不是高度。** 输入环和焦点环必须在视觉上区别于传达层深的阴影。

## 结构与层级

| 角色     | 用途                     | 必需关系                         |
| -------- | ------------------------ | -------------------------------- |
| 基础内容 | 建立参考平面             | 保持在临时表面和浮动表面之下     |
| 浮动表面 | 在基础之上呈现内容       | 使用与其交互角色相称的深度       |
| 边界提示 | 将表面与其后方内容分隔开 | 支持高度而非与之竞争             |
| 逃逸路径 | 使浮动表面保持可见       | 防止被较低容器意外裁剪           |

## 状态表示

静止内容、浮动菜单、持久覆盖层和瞬态反馈必须构成连贯的深度序列。焦点环或校验环不得暗示控件已移动到另一层。

## 响应式与输入行为

- **DR5 — 深度在重新定位后保持不变。** 表面可以移动或调整大小以适应视口，但其在层级中的感知位置必须保持稳定。
- **DR6 — 浮动内容逃逸容器。** 响应式裁剪或滚动不得使表面出现在它本应覆盖的内容之下。

## 无障碍意图

层顺序必须能通过焦点移动、语义和内容关系来理解，而不仅仅依赖阴影。高对比度呈现应在柔和阴影不可用时仍保留清晰边界。

## 代表性示例

- 菜单出现在其触发器和附近的粘性内容之上，且不使用夸张的阴影。
- 当视口受限时，模态框和瞬态通知保持其相对层级。
